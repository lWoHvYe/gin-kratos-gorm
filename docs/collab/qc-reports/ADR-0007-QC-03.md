## 1. 结论

**BLOCKED。** v0.3 对 QC-ADR-02 的整改是实质的：承诺状态机与 `SUM(RESERVED)`（Q-21）、三层额度（Q-22）、零元固定组级（Q-23）、CAS 败者分支（Q-24）、TOCTOU 规则（Q-25）、`GetIntent`/`GetPaymentByOrder`（Q-26）、事件兼容假设（Q-27）、Fulfillment 消费 PRE（Q-28）、零元 worker（Q-29）均已落位；**无资金损失级 BLOCKER**。

但本轮仍有 3 项 MAJOR 不在“C-1…C-7 实现前置 + Q-30 人类确认”的允许剩余集合内：

- **Q-31（MAJOR）**：§7 的 TOCTOU 规则“Inventory 不得自行过期释放订单预留”与现有实现冲突——`internal/services/inventory/worker.go:26-33` 的 `RunExpiry` 按 `status='HELD' AND expires_at<=NOW(3)` 释放 **HELD** 预留，这是 PENDING 订单放弃后的安全网；而 PAID 要求所有行 `CONFIRMED`，HELD 的 TTL 释放**不会**产生 `PAID + RELEASED`。ADR 的规则比必要更宽，若按字面“关闭或改为经 Order 取消后释放”，会移除该安全网；且“Inventory 改造”未进入 §17 的 C-1…C-7 与 §13 的假设/前置，§7 的“因此不会出现”把实现改造写成了已保证。
- **Q-32（MAJOR）**：Q-21 的崩溃窗口仍在——Payment 退款成功、发起方 worker 在把承诺从 `RESERVED` 改为 `SETTLED` 前崩溃时，该承诺仍计入 `SUM(RESERVED)`，而同一笔已在 Payment `refunded` 中，下一笔准入会**双重扣减**并误报 `REFUND_ADMISSION_CONFLICT`（已离仓组的第二次部分退款、TCC“部分成功只补未 DONE”会受阻）。ADR 的“完成必须更新承诺”是要求而非原子保证；§11 的日终对账项没有 `order_refund_commitments`，也没有“RESERVED 但 Payment 已退”的关闭/修复规则。
- **Q-33（MAJOR）**：INV-43 的适用范围仅在 §13.15/§17 C-7 由“人类确认”；若人类认可组级解释，SPEC-0002:114 的 INV-43 字面仍要求**所有**退款先准入，canonical 契约与 ADR 的 §5.1 边界仍分叉。§17 的 C-7 是必要条件但不足够，accept 路径也需要 PO 在 SPEC 落一条口径。

## 4. 五个指定攻击点的回答

| # | 攻击点 | 回答 |
|---|---|---|
| 1 | Q-21 公式在“Payment 已退但承诺未 SETTLED（worker 崩溃）”时是否仍双重扣减；是否需要补对账关闭承诺 | **仍会（瞬时）双重扣减**：`SUM(RESERVED)` 含该笔，Payment `refunded` 也含它；窗口直到 worker 重试把承诺置 `SETTLED`。`FAILED_PERMANENT`/人为关闭时承诺可能长期 `RESERVED`，会长期误拒。**需要**补对账/修复（Q-32）：按 `refund_id` 查 Payment 退款事实关闭承诺；准入对“已退未 SETTLED”按已退处理 |
| 2 | Q-25 的 TOCTOU 规则是否与现有 Inventory 过期释放实现冲突；是否把“实现改造”写成“已保证” | **冲突**：现有 `RunExpiry` 释放 HELD（安全网），ADR 的规则按字面要求关闭/改造它；HELD 的 TTL 释放不会造成 `PAID+RELEASED`，规则过宽。ADR 的“因此…不会出现”以该改造为前提，而改造未进入 §17/§13（Q-31）。正确做法：只禁止 **CONFIRMED** 的自发释放，保留 HELD 的 TTL 安全网，并把 Inventory 核查列为前置 |
| 3 | §5.2 两阶段在 `CONSUMED+CANCELLED`、`CancelIfCreated` 超时、Fulfillment 消费 PRE 三条路径上是否收敛到同一结果 | **收敛**：Tx2 对 `CANCELLED` 写 PRE（ADR:265/268）；超时保持 `PENDING_REMOTE` 由 worker 重试，最终 CANCELLED→PRE 或 SHIPPED→POST（ADR:262-267）；NONE 分支由 Fulfillment 消费 PRE 调 `CancelIfCreated`（ADR:257），Order 崩溃不影响 outbox。三路径的组最终不可发、admission 结果为 PRE/POST 唯一。残余：Fulfillment 返回 `ALREADY_SHIPPED` 的异常处理（Q-35） |
| 4 | 支付级退款与 INV-43 的边界是否仍需 SPEC-0002 回写；§17 是否足够 | **需要回写**：§17 C-7 的“人类确认”能记录裁决，但若认可组级解释，SPEC-0002:114 的 INV-43 字面仍宽，canonical 契约未变（Q-33）。§17 是必要条件但不足够：应在 SPEC 落一条适用范围（或升版/变更记录），ADR 引用该落点 |
| 5 | 是否还有代码级 BLOCKER | **无资金损失级 BLOCKER**；Q-31/Q-32/Q-33 为 MAJOR（其中 Q-31/Q-32 是设计/实现前置，Q-33 是人类/契约）。它们不在“C-1…C-7 + Q-30”的允许剩余集合内，因此按本轮给定标准判 **BLOCKED**，需 v0.4 或把这 3 项显式加入条件 |
