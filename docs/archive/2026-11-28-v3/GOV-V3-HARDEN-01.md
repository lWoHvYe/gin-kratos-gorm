change_id: GOV-V3-HARDEN-01; 级别: 治理变更; 状态: 草案，未审查、未批准，不得写入 Live。

## 1. 为什么改

v3.0 的结构是对的，但有三个缺口，都是“作者一个人握笔”带来的：
- 审查范围由作者划定，可以越切越碎。
- “已验证”没有仓库内的证据锚点，证据可以放在未跟踪的临时目录，审查时代码可以未提交。
- 审查者的步骤清单和非规范指南，把宪法里的硬要求降成了“可选”“备注”。

另有 5 条设计时提过的设想没有落进文件 (见第 2、3 节的 C2、C3、C4、C6)。v3.0 自己要求的试点也没有跑。

原则：规则只写结果，不写步骤。作者和审查者都是有判断力的 agent，方法由它们自己定。

6. 不能复跑时写明原因/未覆盖，并引用台账里的人类书面豁免；没有豁免不得 PASS。
7. 一次给全所有 blocking 问题；只追 blocker；作者修完后只复失败项+diff；不给补丁；发现设计缺口就停代码，回 Spec/ADR。

## 8. 分析结论（author triage，2026-11-28；非独立审查）

**结论：部分接受，不能整份写入 Live。** 提案对三个缺口的诊断成立，但 C3/C5 及部分 A4 会引入新的误阻断；D1/D2 仍需独立 reviewer/human 决定。

### 接受（但需改写）

| 项 | 处置 | 理由/落点 |
|---|---|---|
| A2 / C2 冲突规则 | 接受 | 改为 AGENTS §2.2 一条；宪法落点应为第 16 条（人类裁决），不是第 4 条（Spec 权威） |
| A4 scope 由审查者确定 | 接受 | 作者声明只是输入；必须列未覆盖 AC/路径 |
| A4 “已验证”需仓库内证据 | 接受，限代码阶段 | Spec 阶段没有 committed HEAD；不能把“未提交草案”判死。需 D2 决定 Spec 阶段口径 |
| A4 高风险未解决不得 PASS | 接受 | 与宪法 9/12 一致 |
| A4 不能复跑需台账豁免 | 接受 | 与宪法 6 一致；无豁免不得 PASS |

### 拒绝/改写

| 项 | 处置 | 理由 |
|---|---|---|
| C3 “同一路径 2 处以上同类分支即停” | **拒绝** | 机械阈值，不是结果规则；合法兼容/状态机可能有多分支，应由 INV/ADR/AC 判定，不能按计数阻断 |
| C5 业务裁决题选项必须给现有代码 `文件:行号` | **拒绝** | 新能力/新行为没有现有代码可达性；这是把 AC 可达性错误套到裁决选项 |
| A4 “独立 oracle 必需” | **改写** | 仅“标已验证”的 claim 需要独立 oracle；matrix/mutation 仍是可选辅助，不能变成所有 review 的强制工具 |
| 归档 reviewer checklist | **延后** | 它是非规范、按需读；删除它不会修复硬规则，且会损失操作辅助。先保留，观察试点 |
| 移动旧 PAY QC 报告 | **不接受为本变更一部分** | 历史证据不重写；如要清理，另案归档并保留索引 |
| D1 “把 live 全文+增量一次审掉 pending” | **不能由作者关闭** | 必须独立 reviewer 出 PASS；作者只能整理范围 |
| D2 base/head 对治理/Spec 阶段同样强制 | **待人类决定** | 治理/Spec 阶段常在工作树审草案；未决定前不写死 |
| D7 积压项 | **延后** | 不占本变更；试点后另列 |
