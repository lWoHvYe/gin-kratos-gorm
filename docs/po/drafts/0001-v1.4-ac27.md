## 1. 问题

SPEC-0001 v1.3 的 AC-27 原文使用 Gherkin 步骤：

> 以下为 v1.3 原文的**引用**（用于对照，不是新 AC 的写法）：
>
> **AC-27** 已退款未发组不卡住订单
> Given 拆量订单 G2 退款完成、G1 正常发货
> Then 订单投影按 G1 推进；G2 不得让订单停留在 ALLOCATED 或阻塞 G1 发货
> And G2 的预留释放/运单取消不构成 §6.6 禁止的组合；订单生命周期仍为 PAID/ALLOCATED/SHIPPED，
>     G2 的退款进度由 refund_state 表达

该文本在 v1.3 批准时未被改写，属于宪法 v1.2.0 明示的**基线迁移债务**。本次只做语法迁移：

- 行首不再出现 `Given/Then/And`；
- 每条断言使用 `WHEN/IF/WHILE ... THE SYSTEM SHALL ...`；
- 句内允许 `AND/OR` 组合条件；
- 语义、断言强度、AC 编号、测试追溯均不变。

## 2. 拟替换文本（v1.4-draft）

**替换位置**：`docs/specs/0001-fulfillment-quantity-split.md` §9“状态与投影”中的 AC-27 整块（v1.3 第 571–575 行）。替换后如下：

```text
**AC-27** 已退款未发组不卡住订单
- WHEN 拆量订单的 G2 已退款完成且 G1 正常发货，THE SYSTEM SHALL 按 G1 的履约进度推进订单投影；
  G2 不得使订单停留在 `ALLOCATED`，也不得阻塞 G1 发货。
- WHILE G2 已退款完成（`refund_state=REFUNDED` 且许可 `REVOKED` 或运单 `CANCELLED`），
  THE SYSTEM SHALL 保持订单生命周期为 `PAID/ALLOCATED/SHIPPED` 之一，并只通过 `refund_state`
  表达 G2 的退款进度；不得把退款进度写入 `orders.status`。
- WHEN G2 的预留已释放或运单已取消，THE SYSTEM SHALL 按 SPEC-0001 §6.6/§6.6.1 判定该组合合法，
  不构成 §6.6 的禁止组合。
```

> **范围限定（QC B-3）**：本 AC 只覆盖“已退款完成”的 G2（`refund_state=REFUNDED`）；`REFUNDING`（退款进行中）不属于 AC-27 的原文语义。本草案**不**把进行中写入“已完成”。若未来确需覆盖进行中，必须另立独立 EARS AC 并标注“语义扩展”，届时不得再称“仅语法迁移”。

### 2.1 语义保持对照

| v1.3 原文断言 | v1.4-draft 对应 EARS | 是否改变 |
|---|---|---|
| G2 退款完成、G1 正常发货 | `WHEN ... G2 已退款完成且 G1 正常发货` | 否 |
| 订单投影按 G1 推进 | `THE SYSTEM SHALL 按 G1 的履约进度推进订单投影` | 否 |
| G2 不得让订单停留在 `ALLOCATED` | `G2 不得使订单停留在 ALLOCATED` | 否，保留同一禁止 |
| G2 不得阻塞 G1 发货 | `也不得阻塞 G1 发货` | 否 |
| G2 预留释放/运单取消不构成 §6.6 禁止组合 | `WHEN G2 的预留已释放或运单已取消 ... 判定该组合合法` | 否，引用同一 §6.6/§6.6.1 |
| 生命周期仍为 `PAID/ALLOCATED/SHIPPED` | `WHILE ... THE SYSTEM SHALL 保持订单生命周期为 PAID/ALLOCATED/SHIPPED 之一` | 否 |
| G2 退款进度由 `refund_state` 表达 | `并只通过 refund_state 表达 G2 的退款进度` | 否；`AC-25/INV-01` 为解释性引用，不新增断言 |

> 说明：原文“不得让订单停留在 ALLOCATED”中的“停留”在 EARS 中改写为“不得使订单停留在 `ALLOCATED`，也不得阻塞 G1 发货”，未新增任何状态值或判定条件。对照表只列 AC-27 原文出现的断言；`AC-25/INV-01` 仅作解释性引用，不新增断言。
