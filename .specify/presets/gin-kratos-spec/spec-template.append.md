## 附录 A 对照（宪法必备内容）

> 本节对照 `.specify/memory/constitution.md` 附录 A。Spec Kit 原生章节可保留；每个问题都要有落点，不适用写“无”。

- **业务规则与验收标准**：每条 AC 可判定，能落到测试、契约检查或可观测指标；EARS 的 `WHEN/IF/WHILE ... SHALL` 或 Spec Kit 的 `Given/When/Then` + `FR`/`SC` 均可；金额、状态、并发写出拒绝错误；`SHALL`/`THEN`/`MUST` 后不得接不可判定形容词。
- **状态所有权**：每个核心状态字段的唯一事实来源；不得把多个状态揉在一个字段里。
- **契约与异常恢复**：幂等、最终一致性、持久恢复所有者；并发、超时、崩溃、部分成功、网络脑裂下的表现；状态机不得有死胡同；协议/数据模型/状态机链接 ADR。
- **可达性检查**：每条 AC 的触发态在现有代码里怎么到达，给 `文件:行号`；到达不了标 `[不确定]`。
- **假设与不确定性**：所有底层依赖风险。
- **业务裁决题**：需要人类决定的业务取舍，每题带编号选项；没有写“无”。
- **验收状态表**：AC 编号、状态（未验证/有引用/已验证/historical）、检查类型（测试/契约检查/可观测指标）、证据路径、审查者；新 Spec 可用 `<change_id>-AC-<n>`，长期 Spec 沿用原 `AC-<n>`，退役编号不复用，AC 编号不要求等于 change_id。
- **延期清单**：AC/工作项、owner、expiry、reason；到期未关闭阻断对应范围；不得删行、批量续期或用新 change_id 规避；延期≠豁免，豁免按宪法 17 另行登记。
