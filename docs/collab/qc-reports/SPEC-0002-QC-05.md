## 1. 结论

**BLOCKED。** N-37 的金额前置、N-38 的 Order/Fulfillment 两段拆分、N-40 的准入结果归属、N-41 的取消重试、N-43 的释放顺序、N-44 的对账、N-45 的并发集合、N-46 的已离仓列举、N-48 的 0001 §7.1/§7.5、N-49 的 `shipped_at` 均已落位（详见 §2）。

阻断来自 **N-39 的整改副作用**：

- **N-50（BLOCKER）**：AC-51 的 CAS 失败分支写"转为 AC-50 的已支付分支并告警"（`:211`），但 `tcc:<payment_no>` 是**订单级**退款申请（`:210`），而 AC-50 的准入是**组级**、S8 的每条申请只带一个 `组`（S8 `:78`）。多组订单上：订单级金额必然大于单组剩余额度，会触发 AC-50 `:195` 的 `REFUND_ADMISSION_CONFLICT`（补偿卡死）；若按单组金额拆，则未覆盖的组仍可发货，形成"已退款 + 仍发货"。该路径既没有定义组范围/拆额，也没有定义 CAS 失败后是否阻断该单全部组的履约。这同时是窗口 2/4 的资金级缺口。

其余：**N-51**（零元单组在 AC-50 金额门上的判定二义）、**N-52**（AC-50 分支未穷举 + "无运单"分支对 `CONSUMED` 置 `REVOKED` 违反 §5.2）、**N-53**（许可行 CAS 被 Ship 抢先时的败者路径未定义）。

## 3. 五个定向攻击的回答

| # | 攻击点 | 回答 |
|---|---|---|
| 1 | AC-50 的"金额 = 剩余额度"是否在所有分支可判定（零元单、已部分退款组、未离仓无运单） | **主干可判定，三个边界不可判定。** 已部分退款组：已离仓按 `:201/:202`（`POST`），未离仓按 `:196` 拒绝——可判定。未离仓无运单：`:200` 有明确分支（置 `REVOKED`、`PRE`）。**零元单**：组剩余为 0，"本次金额 0 > 0"不成立，但 `:195` 的"该组已全额退款"对 0 金额组是否成立未定义——若判成立则 `REFUND_ADMISSION_CONFLICT`，AC-40 `:133`"只释放或回库"的售后路径被卡死（N-51）。**许可 `REVOKED`/`CONSUMED` + 运单 `CANCELLED` + 剩余 > 0** 无分支（N-52）。**TCC 订单级金额** 无法映射到组剩余（N-50） |
| 2 | AC-48 的 Order/Fulfillment 两段是否仍有同输入两码；`SHIPMENT_CANCELLED` 返回方是否一致 | **两段拆分成立，无同输入两码。** Order 的准入（`:181-184`）只回答"许可是否允许"，Fulfillment 的 Ship（`:185-186`）回答"运单是否可离仓"；同一输入最终只有 `SHIPMENT_CANCELLED` 一个结果。`SHIPMENT_CANCELLED` 在 §5.6 `:355`、§5.2 `:306`、AC-48 `:185` 三处均归 Fulfillment，一致。唯一需要注意的是 Order 对 `CONSUMED` 同 `shipment_no` 返回"幂等已授权"不是发货成功，调用方必须按 `:185` 读运单状态；AC 已显式要求 |
| 3 | AC-51 CAS 失败转已支付分支是否会导致"已退款又 PAID" | **不会产生第二个 `PAID`，但会产生资金/履约缺口。** CAS 失败说明订单已被支付确认推进为 `PAID`，本分支不再写生命周期；问题是随后"转 AC-50 已支付分支"只做组级退款，没有定义：①订单级 `tcc:<payment_no>` 退款如何拆到多个组（S8 每条申请只有一个 `组`）；②未覆盖的组是否仍可发货。若只退部分组，未退组仍可发货 → 已退款 + 发货；若按单组金额退，订单级金额大于组剩余 → `REFUND_ADMISSION_CONFLICT`，补偿卡死（N-50） |
| 4 | 准入结果归 Order、申请归发起方后，崩溃恢复是否仍可判定（窗口 2） | **业务层可判定。** Order 先持久化结果再返回（§2 `:90`）；重试先读 Order 结果（AC-50 `:203`）；结果缺失时重跑准入；许可 CAS 成功但运单取消未完成时在运单行 CAS 重试取消（§2 `:90`、AC-50 `:207`）。残余：重跑时"已是目标状态（`REVOKED`）视为成功"的判据未写，需 ADR 固化（N-57），但不影响业务终态 |
| 5 | 是否还有死胡同/非法迁移/无错误码/不可判定的"或" | 有：N-51（零元单组在 `:195` 与 AC-40 之间二义）、N-52（`CONSUMED`+无运单分支置 `REVOKED` 违反 §5.2 `:305`；`REVOKED/ CONSUMED`+`CANCELLED` 无分支）、N-53（许可行 CAS 被 Ship 抢先时无败者路径）、N-54（§5.3 引用 §5.5 不存在的 `REJECTED/CANCELLED` 状态）、N-55（AC-45/47/59 无码、AC-44 ack 缺口） |

### 4.1 BLOCKER
