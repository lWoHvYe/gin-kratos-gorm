## 1. 结论摘要（P0）

1. **仅单组订单发 physical release**：Order 的 `group_count == 1` 且当前组 `PRE_SHIP_REVOKED` 时，立即发 `release_scope=order_reservation_full`。
2. **多组订单（`group_count > 1`）不产生 release**：退款准入可成功，但**不写 outbox**、不释放库存，reservation 保持原状；仅日志/告警，P1/人工处理。
3. P0 不做历史回填，没有扫描 worker；多组仅日志/告警。
4. Inventory consumer **只处理单组 event**，按整笔 reservation 执行 `Release` 或 `TccCancelConfirm`，**不要求 quantity 匹配**；`group_no` 仅审计。
5. `POST_SHIP_ALLOWED` 不写 release；已发货组走 AfterSales restock。
6. 零元/正金额同一单组 event 路径；零元仅跳过 Payment。
7. B2 保留 `system_shortage`；`payment/legacy_expired` 拒绝（T2 扩展）。
8. B3 生产回填 **deferred**（当前无生产数据）；不新增回填/scan 任务。
9. C-04 release event 不需单独人类 Approve；本设计/C-04 增量仍需 QC/Architect。

## 2. 单组 release

### 2.1 判定

- `group_count = order_fulfillment_groups` 中该 `order_no` 的组数（含所有状态；历史 G1 计 1）。
- 仅当 `group_count == 1`、当前组 `PRE_SHIP_REVOKED`、订单未 `POST` 时发 event。
- `group_count > 1`：不发 event、不写 outbox；日志/告警；库存保持 reserved；P1/人工。
- 当前组 `POST_SHIP_ALLOWED` 或已发货：不发；AfterSales restock。
- `order_items` 缺 group/仓：fail-closed，不猜 G1/W1。

### 2.2 Event（C-04 增量）

```json
{
  "schema_version": 1,
  "release_scope": "order_reservation_full",
  "group_count": 1,                 // 必填；P0 只能 1
  "release_id": "rr:<refund_id>",
  "refund_id": "tcc:<payment_no>:<group_no> | <after_sale_no> | <shortage_refund_id>",
  "order_no": "ORD...",
  "group_no": "G1",                 // 单组触发组，仅审计
  "covered_group_nos": ["G1"],      // 可选审计；不得作为唯一判据
  "source": "tcc | system_zero | system_shortage | aftersale",
  "reason": "TCC_COMPENSATION | ZERO_AFTER_SALE | SHORTAGE_REFUND | AFTER_SALE_REFUND",
  "items": [{"sku_id": 1, "quantity": 3, "warehouse_id": 1}],
  "requested_at": "..."
}
```

- `release_scope` 当前唯一值 `order_reservation_full`；**`group_count` 必填，P0 producer 只能写 1**。
- `group_count` 是 Inventory 的唯一安全判据；`covered_group_nos` 可选、仅审计，不得用它替代 `group_count`。若提供，长度必须等于 `group_count` 且包含 `group_no`，否则 Permanent/DLQ。
- `items` 是**单组订单 reservation 的全量**（按 order/sku/warehouse 聚合），不是部分 group 数量。
- `group_no` 只审计；`covered_group_nos` 可选，不参与释放判定。
- `warehouse_id` 必填；不得默认 W1。
- `release_id` 幂等；重复 event Inventory no-op。

### 2.3 Producer

- 在 `AdmitRefund`/`admitZeroRefund` 准入事务内：
  - 先判定 `group_count == 1` 且 PRE；
  - 是 → 写 `group_count=1`、append outbox；append 失败回滚准入；
  - 否（多组/POST）→ **不 append**；日志/告警；准入本身可成功，库存不释放。
- 多组不产生占位、不产生 PENDING、不重试、无 scan worker。
- 零元/正金额同路径；零元无 Payment。

### 2.4 Inventory consumer

- 先校验 `group_count == 1`；**缺失/0/!=1 直接 Permanent/DLQ，不释放**。
- 只接受 `release_scope=order_reservation_full`；按 `order_no` + items 的 `(sku,warehouse)` 找整笔 reservation：
  - `HELD → Release`；
  - `CONFIRMED → TccCancelConfirm`；
  - **不要求 quantity 匹配**；`group_no` 不参与 reservation 身份；
  - 不存在/已释放 → 幂等成功；
  - 超时/部分失败 → 重试；永久失败 DLQ/告警；不 ACK 半成功。
- 多组 producer 不写 event；若收到 `group_count>1`/缺失的 event，按契约错误 DLQ/告警，不释放。
- Fulfillment 不消费；AfterSales restock 独立。

### 2.5 零元/已发货/多组

- 零元单组 PRE：同 event；S19 DONE 后 AfterSales REFUNDED。
- 零元多组：不发 release；库存保持；P1/人工。
- 已发货组：不 Release；AfterSales restock。
- 多组任何情况：不释放；即使所有组退款，也 reserved，P1/人工。

### 2.6 C-04/C-05

| 项 | 结论 |
|---|---|
| C-04 | event registry/JSON schema + **必填 `group_count`** + `release_scope` + full-release consumer semantics；无新 RPC；无 group reservation 字段。 |
| C-05 | **无 Inventory 迁移**；不新增 group 列/release receipt/scan 表。 |
| 旧 event | `inventory.compensation_requested` 保持原语义；新 subject `shop.inventory.refund_release_requested.v1`。 |
| 目标引用 | SPEC-0002 v1.9 INV-44/AC-50/AC-67/AC-68；ADR-0007 Amd1；T1.4a Addendum R-A。 |

## 3. 零元 AfterSales 持久 task

- 复用既有 `after_sale_refund_tasks`（PENDING/PROCESSING/DONE/FAILED_PERMANENT + lease），无新表/迁移。
- 流程：`ensureRefundTaskTx(PENDING)` → claim + lease → `AdmitRefund(source=system_zero, amount=0)` → 零元短路（CONSUMED 先 CancelIfCreated）→ S19 DONE → AfterSales 本地事务 `REFUNDED/CONSUMED` + task DONE；**不调用 Payment**。
- Cancel 失败：不写 S19；task 回 PENDING 重试；超限 `FAILED_PERMANENT` + 告警，不伪造 REFUNDED。
- S19 已写但 AfterSales 崩溃：重试幂等；不重复 S19/release。
- return-refund 先 restock done 再 AdmitRefund；零元不例外。
- S19 DONE 在 Order 准入事务提交时（含适用 outbox）；AfterSales `REFUNDED` 后 task DONE 同事务；物理 release 异步，失败重试/告警，不回滚 S19。

## 4. B2 / B3

### 4.1 B2 source

| 路径 | AdmitRefund source | release source/reason |
|---|---|---|
| 普通售后 | `aftersale`（空串兼容） | `aftersale` / `AFTER_SALE_REFUND` |
| 零元 | `system_zero` | `system_zero` / `ZERO_AFTER_SALE` |
| TCC | `tcc` | `tcc` / `TCC_COMPENSATION` |
| SYSTEM 缺货 | **`system_shortage`** | `system_shortage` / `SHORTAGE_REFUND` |
| `payment`/`legacy_expired` | **拒绝** `REFUND_RELEASE_SOURCE_UNSUPPORTED` | T2 扩展，不得默认 aftersale |

- `internal/services/aftersales/workers.go:389-391` 的 SYSTEM 缺货 worker 必须改为 `system_shortage`；`aftersale` 仅普通售后。

### 4.2 B3

- **生产回填 deferred**：当前无生产数据；不做历史 backfill；不新增回填/scan/receipt。
- 若 dev/UAT 已有 PRE/S19 无 release，作为环境清理单独处理，不进入 P0 设计。
- 多组库存保持 reserved 属于 P0 已知行为，不是回填缺口。

## 7. 已知缺口

- 多组库存不释放：P0 已知行为，P1/人工；不是回填/scan 缺口。

- `order_items` 缺组/仓：fail-closed，不默认 G1/W1；正确行为。
