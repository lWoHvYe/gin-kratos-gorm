## 2. R-B：POST 组 commitment 时机

- **判决**：T1.2b 的 Tx1 只写 application（不写 commitment）；**T1.4a 准入阶段**在同一事务写 `order_refund_admissions(POST)` + `order_refund_commitments(RESERVED)`；T1.4b 仅在 `ADMITTED` 且 RESERVED 存在时进入 PAYING；不得 Tx1 写、不得打款后补、不得重复创建（`:56-60`）。
- **依据**：ADR §4.1.2 step 3 只描述 Tx1；AC-65/INV-48 要求打款前占用组剩余额度。裁决把“Tx1 不写”与“admission 写”分开，符合契约意图。
- **判定**：**可接受**；需在 T1.4b 的额度门禁测试中覆盖“重复/并发不产生第二条 commitment”。

## 3. R-C：零元先取消后事务

- **判决**：允许零元 `CONSUMED` 先 `CancelIfCreated`，成功后再单事务写 admission + `refund_applications(system_zero, DONE)`；取消幂等、失败不写 S19、重试幂等（`:66-69`）。
- **前提**：T1.4b 在调用 `AdmitRefund` 前必须有持久 AfterSales refund task（lease/retry）；无持久任务时**必须先持久意图再远程取消**（`:67`）。
- **风险**：T1.4a 当前是同步调用；若进程在“取消成功、事务未提交”之间崩溃，会没有 S19 且当前调用方无持久 task，只能依赖 T1.4b 的 task 重试。Addendum 已把该前提写成条件，T1.4a 不批准实现本身，因此**不构成 Addendum 的 BLOCKER**；但 T1.4b 必须把“先持久 task、再远程取消”做成硬顺序，不能只写“允许先取消”。
- **判定**：**有条件接受**，条件与 Addendum 一致。

## 6. 非阻断提示

1. **C-04 release 事件字段**：R-A 要求 `refund_id/order_no/group_no/items/warehouse_id`；当前 `inventory.compensation_requested` 只有 `order_no/items`。请在 C-04 评审时明确“扩展现有 subject 的 payload（不新增 RPC）还是新增版本化事件”，避免 T1.4b 无法按组释放。
2. **R-C 的持久 task 顺序**：T1.4b 必须“先写 AfterSales refund task（lease/retry），再 `CancelIfCreated`”，不能只允许“先取消后事务”；否则崩溃窗口仍无重试。
3. **R-B 的重复保护**：T1.4b 进入 PAYING 前需断言 POST 组 `RESERVED` 已存在且唯一；T1.2b 的 Tx1-only 测试仍应保留“无 commitment”断言。
