## 2. 实际经过（简）

1. 初始目标只是分析/执行 `docs/convert/ROLLOUT.md`，随后收窄到治理与 PAY-SETTLE T5。
2. 先尝试 bugfix 特殊路由；后认为问题在治理，改为 AGENTS/宪法大改。
3. v1/v2 治理草案均被 reviewer FAIL；live AGENTS/宪法曾被直接修改后又回退。
4. 尝试 A1/A2 Spec 权威设计；A2 发现“原样迁移 0001/0002”不可能（相对链接/0002 §15 镜像）。
5. 做 v3 设计包；review 发现 adoption/pilot/Spec 布局/AC 状态/ADR-0009 冲突，FAIL。
6. 决定拆成 process-only trial；先在分支落地 v3 core。
7. 人类要求“不要留尾巴/一轮完成迁移”，于是直接完成 0001/0002 单布局、index、sdd historical、ADR-0012、v3 同步，并合并 main。
8. 迁移后检查链接/命令边界；补 0001/0002 无 plan 的 `--paths-only` 说明；加宪法 Article 20 防过程膨胀；写本复盘。

## 3. 根因

1. **范围膨胀**：bugfix、治理、Spec 权威、迁移、checklist 被混成一个大改；每加一项就多一组冲突。
2. **旧文本当兼容基线**：反复试图让旧条款“合理化”，而不是先抽不变量、替换机制。
3. **review 当设计**：reviewer FAIL 后继续补文本，没有停止/分类/重置；2 轮规则没有真正执行。
4. **draft 写 live**：未批准文本直接改 live，造成回退和“draft 是否生效”的悖论。
5. **没有固定目标/指标/时间盒**：每轮都在加文档，无法判断何时完成。
6. **先做周边，后做主线**：checklist/guide/ADR 模板/多轮 review 先于核心迁移。
7. **迁移/权威拆得太晚**：先做 process-only，再把 Spec 布局留成尾巴；最后被迫二次收口。

## 4. 有效做法

- Invariant Map：先分“保留/替换/退役/延后”，不再逐条兼容旧文本。
- 直接 `git mv` + 只改链接，不复制、不重写业务/AC。
- 唯一 index + `Spec.md` 指针 + `docs/specs` 重定向，权威面清晰。
- ADR-0012 明确取代 ADR-0009；没有静默改写。
- 迁移后做相对链接检查，0 断链；补命令边界。
- 人类直接决策“完整迁移/不留尾巴”，终止了反复设计。

## 5. 仍存风险（不隐藏）

- 独立 reviewer 尚未对最终 diff 出 PASS；commit trailer 写的是 human direction/review pending，没有冒充 review。
- `0001` 为 frozen reference 且没有验收状态表：行为/AC 定义仍权威，但不再新增/改 AC；这是明确选择，不是遗漏。
- `0002` active，AC 状态以 §15 为准；§15 与旧 TSV/历史台账的关系没有重写。
- 历史台账、旧 `docs/po`/`docs/implementation` 仍可能引用旧路径；本轮不重写历史记录。
- v3 的 PASS/SCOPED-PASS/Release、AC/INV 编号等语义仍有可细化空间；本轮没有继续扩设计。
- 没有跑 pilot 指标；v3 的收益尚未用数据证明。

## 6. 已做的核心调整（防复发）

宪法新增 **Article 20 变更治理（防过程膨胀）**：

1. 一个 change 只解决一个问题；不得把治理、契约、迁移、工具改造混在一起。
2. 草案不得写到 live；live 只放评审通过/人类批准的文本。
3. 同一问题 2 次 review FAIL 必须停止、分类、重置；不得用第三版局部补丁继续。
4. 旧文本只作来源；先写 invariant map，不逐条兼容。
5. 大改先写目标/非目标/可验证指标；无指标不做流程重写。

AGENTS §2 已引用 Article 20；后续变更按此执行。

## 7. 下一步

1. 对最终 diff 做一次独立 review；只审正确性/可执行性，不再重开设计。
2. 跑两个真实变更（非 T5），记录 review 轮次/lead time/escaped blocker；无改善就回滚。
3. `main` 本地领先 origin；由人类 push/决定发布。

## 8. 一句话

这次不是技术难点拖了一晚，而是**把“过程”当成了目标**；正确顺序应是：先定不变量与目标，再一次迁移，最后用指标证明，而不是用更多文档解决文档问题。
