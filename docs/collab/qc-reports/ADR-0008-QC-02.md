## 1. 结论

**READY FOR HUMAN ADR APPROVAL（with 7 MINOR）。** Rev 1.1 不是 Rev 1.0 的改词版：四个 BLOCKER 都换了机制，且都能在现有执行器上落地——

1. **Q-01 真正闭合**：`BASE` 改为“投影树内运行 + 显式 `--range=<BASE^>..<BASE>`”，并给出 5 条 `BASE` 不变量（未跟踪 Spec、baseline 止于 AC-68、legacy G-1…G-3、`BASE^` 存在、树干净）+ `git archive` 非 canonical 的判据；变更后证据改为 head 投影（`BASE` 树 + 被审门禁字节集）。实机验证：干净树内 `--range=main^..main` 得 `SUMMARY G-1=0 G-2=0 G-3=0 exit=0`（详见 §5）。
2. **Q-02 按合法路径闭合**：不再由 ADR 解释 AC——SPEC-0003 已升 **v1.4（approved）**，AC-106/112 明文改为 `G-1…G-3 PASS + g4_status=NOT-RUN(not-implemented-at-BASE)`，并限定时限/批准/随 P0b 终止；ADR 头部的“重对齐条款”禁止再解释。这是“改 Spec 而非改 ADR”的正确修法。
3. **Q-03 换成了内容规则**：`PC-*` 11 行同一张表（change-package/QC 报告真实命名/台账行/baseline 行/注册表/GV-S20/GV-S21/gate record/release scope/README/证据），判据是“diff 只追加 + 记录携带 `parent_change_id`”，彻底删除了 Rev 1.0 的 `<change_id>*` 文件名命名空间；L1 写台账/QC 报告不再触发 `TIER_MISMATCH`。
4. **Q-04 给了载体**：GV-S9/GV-S15/GV-S17 统一落 GV-S20 专用 `mode` 行（`waiver` / `approval|bootstrap|release` / `tier`），含固定 `evidence` 键、读取顺序、缺失/冲突/非人类 actor 的行为；G-4 的输入与失效表同步落地。

新缺陷扫描只发现 7 项 MINOR（记录时序、BASE 不变量缺一条、投影提交缺 trailer、G-2 新增文件口径、QC 头字段清单、audit 行“祖先或相等”表述、P0b 自检的预期退出码），均不改变 AC/INV 语义，也不需要改设计形态。
