## 2. BLOCKER（2 条）

### B-1 C-04 draft §2.3/§2.6 仍是旧语义，与 R-2/R-1 冲突

- 位置：`docs/adr/0007-amd1-refundbatch-c04-draft.md:39-59`（§2.3/§2.6）。
- 问题：
  1. §2.3 写 `Σ items > remaining → INSUFFICIENT_REMAINING`；R-2 已裁决 mixed 只校验 `Σ NEW <= remaining`（既有 item 已在 `intent.refunded_cent` 中，不能重复扣）。按 draft 实现会把 mixed（既有 item + 新 item）误拒。
  2. §2.6 写“本次没有任何新写入、全部既有 → `ALREADY_REFUNDED`”；R-1 已裁决“首次持久化 Reply 是最终语义，首次 `REFUNDED` 之后的重放即使全部已存在也返回 `REFUNDED`，只有首次请求时全部已存在才是 `ALREADY_REFUNDED`”。按 draft 实现会让同一 batch 的重放响应漂移，破坏幂等。
- 风险：C-04 若按当前 draft accepted，Order 预检/重放会按错误语义实现，违反 AC-65 的幂等/全成功要求。
- 建议：把 §2.3 改为“`expected_total == Σ all items`；`Σ NEW <= remaining`；既有 item 不重复扣”；把 §2.6 改为 R-1 的“首次持久化 Reply 为准；重放不重算 `status`；仅首次全既有为 `ALREADY_REFUNDED`”。并补 mixed、重放、同 batch 不同 items 的测试断言。

### B-2 C-04 draft §2.7/§2.8 未包含 R-4 的错误码与 R-3 的最终 schema

- 位置：`docs/adr/0007-amd1-refundbatch-c04-draft.md:61-69`（§2.7/§2.8）。
- 问题：
  1. §2.7 只列 `INVALID_BATCH/BATCH_SUM_MISMATCH/INSUFFICIENT_REMAINING/IDEMPOTENCY_CONFLICT/ITEM_CONFLICT/BATCH_UNAVAILABLE`；R-4 明确新增 `PAYMENT_NOT_REFUNDABLE`/`BATCH_STATE_INVALID`，并给出 Order 映射（`BATCH_UNAVAILABLE`→`PAYING` 重试；其余→`MANUAL_HOLD`/终态）。draft 未含这些，Order 无法按契约映射。
  2. §2.8 仍写“建议 `refunds.batch_id`/`payment_refund_batches`”；R-3/0012 已定：`refunds.batch_id`、删除 `uk_refunds_idem`、保留 `uk_refunds_idempotency`、`uk_refunds_batch_item`、`payment_refund_batches`（PK/fingerprint/status/refunded_cent/item_results）。draft 的“建议”与“或”会让实现选择偏离 0012。
- 风险：C-04 accepted 后 Payment/Order 的契约不一致；`PAYMENT_NOT_REFUNDABLE`/`BATCH_STATE_INVALID` 无映射会导致错误被误重试。
- 建议：把 §2.7 补全 R-4 的 8 个 reason 与 Order 映射表；把 §2.8 改为确定 schema（引用 0012），删除“建议/或”，并写明 `refund_id == idempotency_key`、`batch_id=''` 仅 legacy。

## 3. 非阻断提示

1. R-6 已正确要求“C-04 先并入 R-1/R-2/R-4/R-5/R-3，再 QC/Human accepted；accepted 前不得进入 Order 预检实现，也不得把 `fc295e5` 视为实现 PASS”。本报告据此判定。
