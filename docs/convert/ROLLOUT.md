# 协作模型简化与状态清理 (转交版)

| 项 | 值 |
|---|---|
| 性质 | 新模型：主会话是作者，审查者独立审查，人类批准 Spec 和做 Release。规则只约束产物和闸门，不绑定工具；装了 Spec Kit 时可以用它生成 Spec、plan、tasks。本文件同时覆盖旧治理文本和运行状态的清理。 |
| 状态 | 草稿，待人类批准。替换宪法属于 MAJOR 修订，批准前现行规则继续有效。 |
| 起草者 | 内部静态审查 Agent，应人类 2026-11-27 指示。 |
| 基线 | 2026-11-27 本地快照，无 git，行号请对照当前 HEAD；已做过的跳过；与 HEAD 不符的以 HEAD 为准并回报。 |
| 配套文件 | `constitution.draft.md` (替换 `.specify/memory/constitution.md`)、`AGENTS.draft.md` (替换根目录 `AGENTS.md`) |

## 5. 收益检查与停止条件

| 范围 | 收益检查 | 停止条件 |
|---|---|---|
| 替换稿 | 在宪法和 AGENTS.md 中搜 "PAY-SETTLE-01"、"裁决 B"、"过渡条款" 均无结果 | 落地后两周内，规则文件再次出现具体 change_id 的运行状态，回报人类，不追加维护规则 |
| 试点变更 | 每条审查裁决都写了 AC 位移；每个契约变更的人类批准点不超过 2 个 (裁决 2 选 B 时为 3 个) | 出现下列任一情况且没有被拦住，恢复对应的旧控制，只恢复那一条，并记入台账：代码先于批准的 Spec；作者审了自己的东西；用补丁绕过设计问题；为了通过审查而缩小范围或更换 change_id；交付没有真实的测试证据 |
| Spec | 每条 AC 在验收状态表里有检查类型和证据路径；每份 ADR 的决策都有核对项 | 只为填模板而写的章节或 AC 通过了契约审查；含糊 AC 通过契约审查；其他变更使已验证的 AC 失效而没有更新。出现任一情况，回报人类 |
| 必读量 | 按第 1 节的数字 | 两个连续变更之后必读量没有下降，回报人类 |
| 台账 | 重排和归档后，主文件与归档的行数之和等于原文件行数，期间新增的条目除外 | 整理后两周内再次出现第二种插入方向，或同一 change 的条目被拆到两处，回报人类，不追加维护规则 |

## 6. 交给外部 agent 自查

逐项列结果交人类，不要自行改写换稿。

1. 只在你所在环境装了 Spec Kit 时做：`implement` 会不会无人值守连续执行或多 agent 并行，能不能一个阶段一批地停下；`plan`、`implement` 的宪法检查读哪个路径；`specify` 生成的 Spec 缺宪法附录 A 的哪些章节，与 AGENTS 替换稿 §2 的闸门要求冲突的地方列出来。
2. `.specify/` 与 `.dsh/skills/` 是 Spec Kit CLI 安装的官方脚手架 (`init-options.json` 记录版本 1.4.3)，不要修改其中的核心模板和脚本。确认两件事：它们是否被 git 跟踪；如果做 C-2，模板覆盖层应该放在哪个路径，`specify refresh` 会不会覆盖它。
3. 全仓搜索 C-4 列出的停用文件名，列出每处引用和处置建议。
4. CI 对 `docs/**`、`prompt/**`、`.specify/**`、`specs/**` 的触发规则，以及有没有写死 `Tier: L0|L1|L2` 的尾注或 commit hook。
5. 台账里所有未关闭的事项：延期的 AC、豁免、冻结、没有 owner 的变更，逐条列给人类确认。
6. `docs/` 下按角色划分的目录，哪些是历史存档，哪些还在被引用。
7. 对照现行 `AGENTS.md`、`CONVENTIONS.md`、宪法逐条核对：有没有第 2 节没列到、而你认为仍然需要的条款。有就列出来。
8. 记忆文件里引用旧角色、旧分级、旧文件名的条目清单。
