## 1. PENDING_PAYMENT+captured 分支

| 点 | 设计落点 | 判定 |
|---|---|---|
| CAS→CANCELLED | §2.1：在 T1.2 R-3 guard 位置；事务内 `SELECT orders FOR UPDATE` + CAS `PENDING_PAYMENT→CANCELLED`（version/status）；0 行/已 PAID → rollback + `CANCEL_CAS_LOST` → §4.1 组扇出 | **正确** |
| 同事务 | §2.1：成功 → append `order.cancelled` + payment cancel command（outbox）同一 tx；不写 `refund_batches`/`refund_applications`/`order_refund_admissions`/commitment，不改 permit | **正确**；无组级副作用 |
| outbox 失败 | §2.1：整个 tx rollback，CAS 不落，重试 | **正确**；无 CANCELLED 半状态 |
| 不远程调用 | §2.1：事务内禁止远程；Inventory 由 `order.cancelled` consumer 异步 | **正确** |

## 2. Inventory（CONFIRMED/HELD）

- §2.2：`order.cancelled` consumer 按既有 order-level cancel：HELD→`Release`、CONFIRMED→`TccCancelConfirm` 回库；失败重试/告警；Order 不直接改库存；不使用 T1.4b2 的 release event。**正确**。

## 3. Payment-level command

| 点 | 设计落点 | 判定 |
|---|---|---|
| 身份 | §3.1：`refund_id=pay:<payment_no>:cancel`、`source=payment`、`non_effective_capture=true`、`amount=captured/paid`；Payment `Refund` 用同一 `idempotency_key` | **正确** |
| 不使用 RefundBatch | §3.1：单笔支付级退款、无组 items/Σ；RefundBatch 仅 TCC 组级 | **正确**；与 C-04 RefundBatch 解耦 |
| `refundCancelledAfterConfirm` | §3.2：Inventory CONFIRMED 先 `TccCancelConfirm`；写 payment cancel command outbox（可重试）；append 失败返回错误/告警，不只 log；无 captured/payment_no 不写命令 | **正确** |
| `order.refund_requested` | §3.3：T1.5 后 TCC 不发送；consumer 只执行 `pay:<...>:cancel`/legacy cancel-after-confirm；其余 observe-only；最终 observe-only/移除由 Director release 记录另定，drain 前不提前删除 | **正确** |
| 错误/重试 | §3.4：CAS 失败 `CANCEL_CAS_LOST`；无捕获 `PAYMENT_CANCEL_NO_CAPTURE`；outbox 失败 rollback；Payment 超时 `PAYMENT_CANCEL_REFUND_RETRY`；拒绝 `PAYMENT_NOT_REFUNDABLE`/`ALREADY_REFUNDED`；重复事件幂等 | **正确** |

## 4. 无 captured/零元与 C-04/C-05

- §2.3/§3.3：`captured=0`/`pay_cent=0` 不发 payment command，按 AC-46 本地取消/零元路径；无 Payment 客户端/超时 fail-closed，不猜 captured。**正确**。
- §4.1：C-04 `order.refund_requested` payload 增/使用 `refund_id/source/non_effective_capture/amount_cent`，registry 保持兼容，无新 RPC；C-05 无迁移（outbox 事务持久 + Payment 幂等）；不使用 C-04 release event。**影响清晰**。

## 7. 非阻断提示

1. `order.refund_requested` 新增 `source=payment/non_effective_capture/amount_cent/paid_cent/status` 需在 C-04 registry 中登记为**可选/兼容字段**，避免旧 producer/consumer 解析失败；建议在 T1.6-R 的 C-04 增量里写明。
2. `refundCancelledAfterConfirm` 的“Inventory `TccCancelConfirm` 先、payment command 后”是两段；若 command 写入失败而 Inventory 已回库，需用 outbox/任务重试把 command 补上（设计已说“可重试”），建议 R2 验收加“Inventory 成功、command 失败 → 任务重试不重复回库”。
3. `order.cancelled` 的既有 consumer 是否已覆盖 CONFIRMED→`TccCancelConfirm` 需在实现前核对；若只覆盖 HELD，需在 R2 明确补 CONFIRMED 分支。
4. `amount=captured/paid` 的权威读取需在 CAS 前完成；建议 R1 验收明确“captured 来自 Payment `GetIntent`，不用订单快照”，避免用旧金额退款。
