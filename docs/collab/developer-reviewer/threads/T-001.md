## 4. 阻断项

### P0-1 未提交《反妥协自检清单》

- 契约：`AGENTS.md` §1.3（三问：并发/超时/部分成功、状态揉字段/if-else、向现实妥协）。
- 事实：`docs/collab/architect-developer/threads/T-001.md` 只有“验证 / 残余项 / 未覆盖范围”，三问均未作答；`docs/implementation/adr-0005-deviation-register.md` 的“C. 不变量声明”不是自检清单。
- 结论：按 Reviewer 红线，直接 FAIL。

### P0-2 行级“在途占用”未实现

- 契约：`ADR-0005` §6.4 与 §19.1 #12：创建售后单同一事务 `pending_quantity += q`、`pending_amount_cent += amount`；剩余额度必须同时扣 `refunded_*` 与 `pending_*`；“只扣已退款是超退漏洞”。
- 事实：
  - `internal/services/aftersales/refund_lines.go:52` 只查 `refunded_quantity, refunded_amount_cent`；`:73` 的 `remainingCent` 只减已退款；
  - `CreateAfterSale` 只做 `after_sale_amount_ledger` 占用，不写 line `pending_*`；
  - `pending_*` 仅缺货系统退款路径在写（`internal/services/aftersales/shortage_consumer.go:254-258`）。
- 影响：同一行并发售后可同时通过“剩余数量”校验；第二笔退款失败后订单级 `consumed` 仍被占用。未登记偏差、未开线程。

### P0-3 `FREIGHT_RESPONSIBILITY_ENABLED` 缺失

- 契约：`ADR-0005` §13.1（`docs/adr/0005-fulfillment-quantity-split.md:968`）：新增开关，默认 `false`，关闭时回退旧口径并标 `[未启用]`。
- 事实：`internal/platform/config/config.go:52-62` 无该字段，`:543-563` 只解析其他三个开关；责任判定/168h 运费挂起无条件生效。
- 影响：无法按 ADR 灰度/回滚；与 Developer 记忆“freight responsibility 默认 false”矛盾。

### P0-4 重复 `DELIVERED` 事件可提前自动确认

- 契约：Spec AC-20（签收后 24h）、AC-22/AC-35（申诉窗口/申诉优先）、ADR §7.5。
- 事实：
  - `internal/services/fulfillment/delivery.go:113-119`：`due_at = LEAST(due_at, VALUES(due_at))`；
  - `:259-271`：新的 `DELIVERED` 事件（不同 `event_id`）会再次 upsert 该 job；
  - `:486` 只判 `dueAt + 60s <= now`，`:551` 只判 `deliveredAt.Valid`，**不判 `now >= delivered_at + 24h`**。
- 影响：重放一条 `DELIVERED`（`occurred_at` 设为昨天）即可把 `due_at` 拉到过去，60 秒后自动确认，实际签收可能才几分钟，用户 24h 申诉窗口被吞。

### P0-5 混提 + 越权

- 契约：`CONVENTIONS` §1（产物所有权）、§5.1（一个 commit 一个主 scope）、§5.2-2（proto/生成物与业务服务拆开，不混提）。

  - `6e4ec31 test(fulfillment)` 实际改 order/aftersales/inventory/pricing 测试；`655ccc7 test(collab)` 不在 scope 词表。
- 影响：闸门只看最后一笔，历史混提未拦截；台账与规则的可信度被削弱。
