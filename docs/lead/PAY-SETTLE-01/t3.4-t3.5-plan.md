# T3.4 + T3.5 Plan（行级准入 + responsibility/运费 + Payment 三层）

| 项 | 值 |
|---|---|
| change_id | `PAY-SETTLE-01`（在途；SPEC-0002 / ADR-0007 Amd1 §4.4） |
| 级别 | 实现变更（行为语义在已批准 SPEC 内；不改 proto/migration） |
| 基线 | `0740286`；T3.1/T3.3 已 PASS |
| 状态 | **Approved（2026-11-27 人类批准）**；本轮只做 Phase 1（行组成/commitment lines）；responsibility/168h/T3.6 未做 |
| 目标 | `AdmitRefund` 从“组金额”升级为“行组成 + 组 Σ + 订单 captured 三层”，并落 `order_refund_commitment_lines` |

## 1. 范围

1. 读取并校验 `AdmitRefundRequest.lines`（`line_no/quantity/goods_cent`）、`responsibility`、`reason_code`、`freight_refundable_cent`；Order **只校验/计算**，不推断责任。
2. 行层 INV-24：每行 `本次行退款 ≤ 行实付 − AfterSales 已退(S14) − 该行在途承诺(S15)`；行合计 + 运费 ≤ 组剩余；总额 ≤ 订单 captured 剩余（三层）。
3. 落库：header `goods_cent/freight_cent/composition_known=1`，`amount_cent = goods + freight`；写 `order_refund_commitment_lines`（`line_no=0` 运费行，`>0` 商品行），行合计必须等于 header。
4. 兼容：
   - `composition_known=0` 的历史承诺只允许整组退款，禁止行级部分（A-03）。
   - 请求不带 `lines` 的旧调用：仅允许“未离仓整组、金额等于组剩余、无行级部分”的兼容路径；否则 `PARTIAL_REFUND_REQUIRES_LINES`。
   - post-departure partial 必须带 lines；未离仓整组也要匹配剩余组成。
5. 责任/运费：
   - `responsibility` 必须是封闭枚举；`reason_code` 配对校验；Order 不推断。
   - `freight_refundable_cent ≥ 0` 且 ≤ 该组未退 `freight_share`/用户实付运费；超出拒绝（`FREIGHT_REFUND_EXCEEDS_REMAINING`）。
   - `UNDETERMINED` 商品照退、运费挂起 ≤168h 的 worker/T3.6 不在本 Plan 内；本 Plan 只校验请求字段。
6. Payment 三层：admission 不调用 `Payment.Refund/RefundBatch`；只读 captured/refunded；commitment/ledger 仍由后续 consumer/T3.5 路径驱动。

## 2. 不做什么

- 不做 T3.2（人工释放 `RESERVED→RELEASED` / release RPC）。
- 不做 T3.6（AfterSales/缺货责任产出接线）；本 Plan 只消费请求字段。
- 不做 168h 运费挂起 worker、行级历史审计表（REVIEW-AUDIT-01）。
- 不改 proto/migration（`RefundLine`/responsibility/freight/0018 列已存在）。
- 不改 payment/fulfillment 服务；Order 只读 Payment。

## 3. 关键校验顺序（Tx1 内）

1. 锁 orders 行；幂等读 `refund_id`（既有）。
2. 校验请求字段/责任枚举/lines 非负、line_no 唯一、Σ goods + freight = amount。
3. 读行实付、S14 已退（AfterSales 事实/本包投影）、S15 在途承诺（`loadGroupRemainingExcluding` 扩展为按行）。
4. 行层、组层、Payment captured 三层校验；任何超限 → 拒绝，零 admission/commitment/outbox。
5. permit 决策（既有 PRE/POST/partial）；只有通过后才写 admission/commitment header + lines。
6. 同一 `refund_id` 重试幂等；并发由 orders 行锁串行化 + 行剩余校验兜底（`order_refund_commitment_lines` 的 PK 是 `(refund_id,line_no)`，不是跨 refund 的同行唯一键）。

## 5. 风险与停止条件

- 现有 `AdmitRefund` 测试（T1.4/T2.x）覆盖金额级；行级改造必须保持这些行为；失败即 stop-the-line。
- 旧调用方不带 lines：如果无法区分“整组兼容”与“部分”，拒绝并要求 lines，不得静默按金额放行。
- 行/组/订单三层任一层缺失或不可读：fail-closed，不得跳过。
- 责任/运费字段不合法：拒绝，不得回退到 Order 推断。
- 若实现中发现 proto/列不足以表达（例如同一行多责任/多运费段），停止并回 Architect/PO，不局部补字段。
