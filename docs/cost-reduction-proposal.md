## 0. 摘要（给人类指挥官）

1. 现行治理体系的流程开销估算为跟 Spec Kit 的 **5-10 倍**（轮次、角色、门禁三重叠加，均为估算）。该成本在 P0/资金/库存/跨服务变更上是净收益，但在轻量变更上保费超过期望损失。
2. 本提案给出五个改造项，目标把边际成本压到 **2-3 倍**（估算），同时**不动六条红线**（见 §2）。
3. 最大的单根杠杆是**门禁机器化**（GOV-CODE-01）：规则成本是一次性的，执行成本是每次变更重复支付的；现行 `scripts/collab_gates.py` 的未完成项已在 CONVENTIONS §7.2 债务清单中。本项只是把既定路线图执行完。
4. 五项中有三项需要人类裁决（分级制、QC 差分审查、门禁委托），已整理为 §7 决策表 D-CR-1...D-CR-5，可一次性批量裁决。
5. **本提案不砍任何一条从四代演变中换来的保证**；所有改造项都是“把执行成本从人肉/Agent 重复劳动移交给机器与分级”，红线部分明确列出不做什么。

## 2. 改造红线（不可触碰项）

| # | 红线 | 保留理由（事故出处） |
|---|---|---|
| R-1 | 每个 subagent 自读宪法原文，禁止摘要传递 | 阶段三 QC 产物命名漂移事故：摘要提级导致不同角色对规则认知不一致 |

| **R-6** | **分级判据与核心契约不可越权篡改** | **防止 Agent 为了逃避重兵审查，私自篡改 L1/L2 的分级判定标准（立法权与执行权分离）** |

## 3. 改造项

### GOV-CODE-01 门禁机器化补全 (P0，无需新裁决，执行既定路线图)

- **现状证据**：CONVENTIONS §7.2 自认三项未完成：G-4、`--release` 模式、“AC coverage”措辞；外部复审 triage 第38条复算：`scripts/collab_gates.py` 仅实现 6-1/6-2/6-3，默认 `HEAD^..HEAD`，输出仍写“AC coverage”（`:339`）；另发现 `.github/workflows/go.yml` 的 paths **不含 `docs/**` 与 `prompt/**`**，即治理文件变更当前完全绕过 CI 门禁。
- **具体改动**（批准后由 Developer/流程所有者执行，改动仅限 `scripts/`、`.github/workflows/`、`CONVENTIONS §7.2` 文本）：
    1. 补齐 G-4 与 `--release` 模式，语义按 CONVENTIONS §5 四种结论（实现 PASS ≠ Release PASS）输出；
    2. 输出措辞“AC coverage”与 CONVENTIONS §6.1 一致的 AC-REF/AC-VERIFIED 语义；
    3. CI 触发路径加入 `docs/**`、`prompt/**`、`.specify/**`，使治理变更同受门禁约束；
    4. 支持 commit range 显式传入 (Review/Release 场景绑定精确 base/head)。
- **成本收益**：一次性开发成本，替代每次变更的人肉核对；是五个改造项中唯一“自我回本”的。
- **验收 (EARS)**：
    - `WHEN 任一受管 commit range 传入 gates 脚本 THE SYSTEM SHALL 输出 G-1..G-4 全部结论并区分 Review/Release 语义。`
    - `IF 治理目录 (docs/prompt/.specify) 发生变更且 CI 运行 THE SYSTEM SHALL 执行门禁，不得静默跳过。`

### GOV-TIER-01 变更三级分级制 (P1，需人类裁决 D-CR-1/D-CR-2/D-CR-4)

- **现状证据**：现行体系实际只有两档一全流程与文档轻量路径 (CONVENTIONS §2)；中间地带（单服务行为变更、既有契约下的缺陷修复）被默认拉满到全流程，或被主观压到轻量，缺少客观判据。
- **具体改动**（批准后落点：AGENTS §2.5 增补分级表；CONVENTIONS §2 增补分级判定节）：

| 级 | 判据（客观，命中任一即升级） | 流程 |
|---|---|---|
| L0 | 不触碰行为/契约：文档修正、注释、格式 | 轻量路径 (现行) |
| L1 | 单服务内行为变更：不动状态机、资金、库存、跨服务协议、权限 | Spec 引用既有条款 + Reviewer 复核 + 门禁机器检查；**无新 Spec/ADR** |
| L2 | AGENTS §2.5 现有触发面：P0/跨服务/资金/库存/权限/状态机拆分 | 现行全流程不变 |

- **分级防作弊**（针对阶段教训“趋利避害会向低成本处塌缩”）：
    1. 分级由 **Lead 初判 + Reviewer 复核**（登记于变更输入包），Dev 不得自报；
    2. 错分处置：发现 L2 被当 L1 执行 -> stop-the-line，冻结并按 L2 重走全流程，错分事件记入 Reviewer 台账；
    3. 争议裁决权归人类。
- **成本收益**：L1 类变更 (估算占日常变更多数) 免除 QC 红队与人类阶梯批准 (估算省 40-60% 单变更开销)，代价是接受“L1 也无独立 QC”的风险，由 Reviewer 复核 + 门禁机器化兜底。
- **验收 (EARS)**：
    - `IF 变更未命中任何 L2 判据且 Reviewer 复核通过 THE SYSTEM SHALL 允许该变更以 L1 流程推进。`
    - `WHEN 发现变更被错分级 THE SYSTEM SHALL 冻结该 change_id 并要求按实际级别重走流程。`

### GOV-QC-01 QC 差分审查 (P2，需人类裁决 D-CR-3——本项削弱一条阶段三保证，属风险接受，必须显式豁免)

- **现状证据**：SPEC-0002 从 v1.6 到 v1.8 的每一版均全量重审 (QC-01...QC-14)，轮次成本是 QC 开销主因。
- **具体改动**（批准后落点：CONVENTIONS §2.1 QC 职责节增补）：
    1. 小版本修订 (Amendment 内的 delta) 允许 QC 只审变更 delta 与其直接关联章节；
    2. **两个强制全量复审节点保留**：主版本升级 (v2.0 类)、Release 门禁前；
    3. 差分审查报告中 MUST 声明“本次未复审章节”清单 (呼应 AGENTS §6.4 未覆盖范围声明)。
- **风险与缓解**：版本间漂移可能逃过 QC (这正是阶段三教训) -> 由强制全量复审节点收口，且 G-4/Release 门禁在机器化后提供结构化核对。
- **验收 (EARS)**：
    - `WHEN Spec 小版本提交 QC 审查 THE SYSTEM SHALL 至少复审其 delta 与直接关联章节，并显式列出未复审范围。`
    - `IF 变更进入 Release 门禁 THE SYSTEM SHALL 先完成一次全量 QC 复审。`

### GOV-SCAF-01 治理产物骨架生成 (P2，低风险，无需裁决)

- **现状证据**：plan.md 的 D/C/T 表格、evidence-matrix 行结构均为固定样板，每次手写填充。
- **具体改动**：由 speckit 技能生成 plan/tasks/evidence-matrix 的**结构草稿** (表头、状态枚举、主权声明行)，内容仍由 owner 撰写。显式声明：治理文档骨架**不属于** `api/gen` 类“禁止手工改生成物”约束 (该铁律仅针对代码生成物)。骨架生成不改变任何文档的 owner 与批准门禁。
- **验收 (EARS)**：`WHEN Lead 发起新 change_id THE SYSTEM SHALL 能从模板生成 plan/tasks/evidence-matrix 草稿，主权声明行 (唯一台账、Owner 固定) 不得缺省。`

### GOV-HUM-01 门禁委托规则 (P1，并入 GOV-TIER-01 实施，需裁决 D-CR-2)

- L2 全部门禁保留人类批准 (现状不变)；L1 的阶梯批准可委托为 **QC+Reviewer 联签** (默认) 或仅 Reviewer (候选，见决策表)；人类保留：宪法修订、分级争议裁决、Release 放行 (任何级别)。
- **验收 (EARS)**：`IF L1 变更通过 Reviewer (或 QC+Reviewer 联签) 复核 THE SYSTEM SHALL 允许其推进而无需人类逐门批准；IF 任何变更请求 Release 放行 THE SYSTEM SHALL 取得人类批准。`

## 4. 实施顺序与依赖

- P0 GOV-CODE-01 (门禁机器化) 一先行：分级制与差分审查的兜底都依赖机器门禁
- ↓
- P1 GOV-TIER-01 + GOV-HUM-01 (分级制，需 D-CR-1/2/4 裁决后实施)
- ↓
- P2 GOV-QC-01 (需 D-CR-3 显式豁免)、GOV-SCAF-01 (独立，可并行)

依赖说明：GOV-QC-01 依赖 GOV-CODE-01 是因为“未复审章节”的收口靠 Release 全量复审 + 机器化 G-4 核对；先机器化再放宽 QC，顺序不可颠倒。

## 5. 明确不做的事 (Anti-scope)

1. 不取消/简化 subagent 自读宪法 (红线 R-1)；
2. 不动契约先行与 Phase 0 门禁 (红线 R-2)；
3. 不合并/移动任何唯一台账与事实所有权 (红线 R-3)；
4. 不为降成本放宽 EARS 强制、fail-closed、stop-the-line；
5. 不引入新机器门禁类型 (宪法 Governance 6 精神：只补齐已定义门禁的实现，不新增规则面)；
6. **不通过修改分级判据来把高风险任务降级为低风险任务 (红线 R-6)**；
7. **不通过伪造测试数据或隐瞒未覆盖范围来推进流程 (红线 R-4)**。
