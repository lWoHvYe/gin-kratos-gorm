# T-003 闸门有效性补强

## 现象（PO 复核 T-002 交付物时发现）

T-002 已 `CLOSED`，`make gates-strict` 输出 `AC coverage: 38/38、SUMMARY G-1=0 G-2=0 G-3=0`。但这份绿灯的**证明力被高估**了，有三处需要补：

1. **G-3 只证明"存在引用"，不证明"断言充分"**。首轮审查时 AC-14 确实缺"多次部分组退款累计 ≤ 实付运费"断言，而当时闸门是绿的；后来靠 Reviewer 人工发现才补上（`TestAC14FreightRefundSixScenarios` 的 cumulative 断言）。机器再绿也拦不住"引用了一个空测试"。
2. **`ac-coverage.tsv` 的 6 条 deferred（AC-22/28/29/30/35/37，expiry 2026-12-15）与偏差登记的到期项，没有任何执行者**。CONVENTIONS §6 写着"到期升级 BLOCKING"，但闸门不读到期的表，规则只活在纸上。
3. **`gates-strict` 默认只扫 `HEAD^..HEAD`**，输出里不打印扫描范围；历史有 4 笔 `[mixed]` 混提。绿不能证明整条分支合规，但输出看起来像"全分支已验"。

## 诉求（给 Architect 的方案要求，不指定实现）

| 项 | 要求 |
|---|---|
| G-3 措辞 | 输出改为 `AC-REF n/38 (references only)`，禁止再用"coverage"这种暗示"达标"的词；`strict` 额外输出 `DEFERRED <n>`（来自 `ac-coverage.tsv`）与 `OVERDUE <n>`（`expiry <= today` 且未 closed） |
| **新增 G-4 到期闸门** | `strict` 读取 `docs/collab/ac-coverage.tsv` 与 `docs/implementation/*-deviation-register.md`，任一条 `expiry <= today` 且状态不是 `closed` → **失败并列出条目与 owner**；到期项必须要么关闭、要么由 owner 显式续期（续期需在 commit 里写明理由，续期后 `expiry` 必更新） |
| 扫描范围 | 支持 `--range`，并在输出第一行打印 `SCAN RANGE <range>`；发布前必须用 `origin/main..HEAD`（或明确声明范围），默认 `HEAD^..HEAD` 仅用于日常 |
| CONVENTIONS 增补 | §4 增加"闸门能力边界"小节：明确"绿 = 引用存在 + 规则未违反"，**不等于**断言充分；断言深度由 Reviewer 人工判定并在审查线程留证 |
| 禁止 | 不得通过放宽 G-3、把 deferred 行删掉、或把 `expiry` 批量延后来"变绿" |

## 验收（Reviewer 执行）

- **A1**：故意把 `ac-coverage.tsv` 某行 `expiry` 改为昨天 → `strict` 失败，输出该 AC 编号与 owner。
- **A2**：正常状态下输出包含 `AC-REF 38/38 (references only)`、`DEFERRED 6`、`OVERDUE 0`、`SCAN RANGE …`。
- **A3**：`--range origin/main..HEAD` 生效，且输出打印实际范围；对历史 `[mixed]` 提交不得静默放过，至少给出提示。
- **A4**：CONVENTIONS §4 出现"能力边界"段落，且 Reviewer 的审查模板引用该段。
- **A5**：本地执行仍 < 10 秒，不依赖网络/Docker。

## 关闭条件

ADR/CONVENTIONS 回写 + G-4 实现 + A1…A5 可复现证据贴入本线程"验证"段；Architect 改 `CLOSED` 并填 `closed_by`。
