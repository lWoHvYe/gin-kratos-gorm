## 运行顺序（ops）

1. 先部署 T2.1 生产者修复（PAID 不得无生效支付）。
2. `order-legacy-backfill` 默认 dry-run；把 `paid_empty/unique/zero/ambiguous` 与 ops 计数对账。
3. 对账通过后 `-apply`；再跑 dry-run 确认 `remaining` 只剩 ambiguous/人工队列。
4. ambiguous 由 `legacy_payment_resolution` 24h SLA/T2.4 worker 或人工处理；本工具不自动选多候选。

## 停止条件

- 生产者未修复或 dry-run 与 ops 计数不符：不 `-apply`。
- 单条 `ensureLegacyResolution` 失败：计入 errors，命令 exit 1；不静默跳过，重跑幂等。
- 若出现结算已写但重复捕获退款失败：工具报错；该订单已离开 PAID-empty 窗口，按 T2.4 既有路径/人工重试，不在批量工具里二次打款。

## 非目标

- 不做 T3 release/Payment、不改 refund admission 协议、不改 migration、不改 `legacy_payment_resolution` 状态机。
- 迁移 0019 的“same transaction”注释为历史；ADR-0010 已澄清独立提交，后续迁移变更时再更新注释。
- CLI 配置/连接错误 exit 2；运行/逐条错误 exit 1（有意 fail-closed）。
