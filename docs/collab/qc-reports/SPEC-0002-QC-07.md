## 1. 结论

**BLOCKED。** N-58 的额度口径（商品 + 运费）、N-59 的"按组剩余拆分"、N-60 的活动组定义、N-61 的 §6 TCC 键、N-62 的 §5.6 表格、N-63 的零元单 `DONE(zero_amount)`、N-64 的准入结果说明、N-65 的历史 G1 处理均已落位（详见 §2）。

阻断在 **TCC 扇出与 AC-50 金额门的交叉**：

- **N-66（BLOCKER）**：AC-51 `:220` 在"Σ 组上限 ≥ 订单剩余 `captured`"时按最大余数法把订单剩余金额分摊到各组，每组分摊额 ≤ 组上限、且可能**小于**组上限；但 AC-50 `:197` 规定**未离仓**组的退款金额必须等于整组退款金额（即组上限），否则返回 `PARTIAL_REFUND_REQUIRES_FULL_GROUP`。因此该情形下只要存在未离仓组，其分摊额就会小于组上限 → 准入必然被拒 → AC-51 `:217`"任一活动组未取得准入结果 → 不得打款、整单可重试"→ 补偿永久卡住。若反向实现为"按组上限准入、按分摊额打款"，则申请金额与打款金额不一致，退款台账/Payment 事实无法对齐。
- **N-67（MAJOR）**：AC-51 `:220` 的第二情形"Σ 组上限 < 订单剩余 `captured` → 只打 Σ 组上限，差额保留为**订单级待退款**并告警"没有定义该差额的所有者、`refund_id`、准入与打款路径（本 Spec 的退款全部是组级）；若差额来自"按责任不可退的运费"，把它标成"待退款"还会导致后续误退。
- **N-68（MAJOR）**：组剩余运费额度被定义为"该组尚未退的 `freight_share`（按 0001 §6.5 **本次**是否可退）"（`:195`），使"组剩余可退上限/已全额退款"变成**随本次责任判定而变化**的量；而 AC-51 `:216/:219` 与 S9 `REFUNDED` 把它当作稳定的组状态。用户责任退货（运费不退）后，组可能既"已全额退款"（本次口径）又保留未退运费；后续商家责任的 TCC 补偿会把它视为活动组并再次退款，而 S9 已 `REFUNDED`（§5.3 `:328`"不允许回退"）无法承接。

## 3. 四个定向攻击的回答

| # | 攻击点 | 回答 |
|---|---|---|
| 1 | 组上限含 `freight_share` 后，未离仓整组退款金额与金额门是否自洽（尤其运费按责任不可退时） | **单次请求内自洽，跨请求/状态不自洽。** 单次：上限 = 商品剩余 + 运费额度，整组退款金额 = 商品剩余 + 本次可退运费，整组金额 ≤ 上限；`:196` 用上限判超退，`:197` 用整组金额判部分退款，`:198` 用整组金额判整组退款，逻辑闭合。运费不可退时：整组金额 = 商品剩余，`:196` 不超上限，`:197` 不成立（金额 = 整组金额），`:198` 进入分支——单次请求没问题。**问题在状态**：运费额度按"本次是否可退"计算，使"组剩余上限/已全额退款"随责任变化；用户责任退货后组可能"本次已全退"但运费仍未退；后续商家责任补偿（TCC）会把它当活动组再退运费，而 S9 已 `REFUNDED` 且 §5.3 禁止回退（N-68） |
| 2 | TCC 的两种情形是否覆盖所有组合；已打款组重试是否被错误计入/重复打款 | **两种情形只覆盖了算术，没有覆盖"分摊额 < 组上限"与"差额无主"两个组合。** ①Σ 组上限 ≥ 剩余 `captured`：分摊额可能小于组上限，未离仓组的 AC-50 `:197` 必然拒绝（N-66）；若 Σ = 剩余（正常会计下的等式），分摊 = 组上限，无此问题——但规格没有声明"Σ 组上限恒等于剩余 `captured`"，反而明确写了"≥"的分摊规则，因此必须覆盖该情形。②Σ 组上限 < 剩余：差额"订单级待退款"没有所有者/`refund_id`/准入/打款路径；若差额是不可退运费，标成"待退款"是错的（N-67）。**重试**：已打款组的上限变为 0/已全退，`:216/:219` 会跳过，不会重复计入；`refund_id + payment_no` 幂等（§6 `:389`）防重复打款——这部分成立。但若一次补偿在"部分组已打款、其余组因 N-66 卡住"的状态，重试仍会卡在未打款组的准入上（N-66） |
| 3 | 零元单 0 元申请走 `PRE_SHIP_REVOKED` + `DONE(zero_amount)` 是否与 AC-40/AC-50 一致 | **一致。** AC-40 `:133` 规定零元单取消/缺货/售后只释放或回库、不调用 Payment，0 元申请标记 `DONE(zero_amount)`；AC-50 `:196` 允许首次 0 元申请（不算已全额退款），`:198` 走 `REVOKED`/取消运单分支，金额 0、无 Payment 调用，`:209` 按 INV-44 释放。残余仅状态机未登记 `DONE(zero_amount)`（N-69），以及 AC-40 把"取消"和"售后申请"写在同一句（取消不一定产生退款申请） |
| 4 | 是否还有代码级 BLOCKER | **有：N-66**（TCC 分摊额 < 组上限时与 AC-50 未离仓整组退款门冲突）。N-67/N-68 为 MAJOR。因此不满足 `PASS WITH CONDITIONS`（该结论只允许剩余 C-1/C-8/C-9） |
