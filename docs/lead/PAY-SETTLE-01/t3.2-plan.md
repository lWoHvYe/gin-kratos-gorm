# T3.2 Plan：退款承诺人工释放（RESERVED → RELEASED）

| 项 | 值 |
|---|---|
| change_id | `PAY-SETTLE-01`（在途；SPEC-0002 AC-62 / D-24 / INV-45） |
| 级别 | 实现变更（行为在已批准 Spec/AC-62 内；不新增退款触发） |
| 基线 | `4f7793c`；T3.1/T3.3/T3.4/T3.5/T3.6 已 PASS |
| 状态 | **Approved（2026-11-27 人类批准 A=ops CLI）** |
| 目标 | 唯一人工入口：授权校验后幂等执行一次 `RESERVED→RELEASED`，只释放额度 |

## 1. 范围

1. 新服务方法 `ReleaseRefundCommitment`（Order 包内）：
   - 加载 `order_refund_commitments`（按 `refund_id`，`FOR UPDATE`）；
   - 仅 `RESERVED` 可释放；`SETTLED`/`RELEASED` → `REFUND_COMMITMENT_CONFLICT`；
   - 金额必须等于承诺头金额，不允许部分/超额；
   - 校验 order/group 归属（若请求带 `order_no/group_no`）；
   - 写 `refund_commitment_releases`（唯一授权/审计行）；
   - CAS `UPDATE ... SET state='RELEASED', version=version+1 WHERE refund_id=? AND state='RESERVED'`；
   - 不动 permit、不改订单生命周期、不关闭组、不写 `DONE`、不调用 Payment。
2. 授权/审计字段（AC-62/D-24）：
   - `release_id`（幂等键）、`authorization_id`（授权单号）、`operator`、`authorized_by`、
     `reviewed_by`（≥100000 分必须非空且 ≠ `authorized_by`）、`reason_code`、`evidence_ref`、
     `authorized_at`、`reviewed_at`、`expires_at`（必须 > now）。
   - `reason_code` 封闭枚举（仅 AC-62 两类触发）：
     `USER_WITHDRAW` / `BUSINESS_REJECT` / `FAILED_PERMANENT` / `MANUAL_ABANDON`。
   - 缺任一字段、越权、超阈值未双人复核、过期 → `REFUND_RELEASE_NOT_AUTHORIZED`，零写入。
3. 幂等/并发：
   - 同 `release_id` 重试：返回首次结果，不重复释放；
   - 同 `refund_id` 不同 `release_id`：`uk_release_refund` + 状态检查拒绝；
   - 并发两执行者：`FOR UPDATE` + CAS + `uk_release_refund`，只一个成功。
4. 触发校验（保守）：
   - `reason_code` 为 `USER_WITHDRAW/BUSINESS_REJECT` 时，若 `refund_applications` 存在，
     其 state 必须是 `REJECTED`/`CANCELLED`；不存在（普通售后 task）则要求 `FAILED_PERMANENT`/
     `MANUAL_ABANDON`，不得用订单 `CANCELLED`/售后关闭冒充。
   - `FAILED_PERMANENT/MANUAL_ABANDON` 只要求人工授权字段；不自动改申请状态。
5. 命令形态（待批准）：
   - **A（已批准）ops CLI** `cmd/refund-commitment-release`：`-apply` 才写，默认 dry-run；
     不需要 proto/迁移；高风险操作不经公网 RPC。
   - B Order gRPC `ReleaseRefundCommitment`：需 proto，授权可由调用方服务校验；
     多一个公网/内网入口。
   - C 两者：先 CLI，后 RPC。

## 2. 不做什么

- 不新增第三类释放触发；不做自动/worker 释放（INV-45）。
- 不恢复 permit、不重建运单、不关闭组、不改订单生命周期、不写 `DONE`。
- 不调用 Payment.Refund；若 Payment 已有退款成功事实，工具拒绝并提示先对账收敛 `SETTLED`。
- 不做部分释放/拆分承诺；不做跨订单/跨组复用。
- 不改 `refund_commitment_releases` 表/迁移（表已在 0018）。

## 3. baseline_impact

- **金额/额度**：只把 `RESERVED` 承诺的 `amount_cent` 从在途占用移出；不改变订单/组 `refunded_cent`。
- **库存/履约**：不涉及；permit/运单/预留不动。
- **权限**：新增人工释放入口；仅 ops 授权角色可执行；≥100000 分双人复核。
- **跨服务**：Order 单服务；不调用 Payment/AfterSales/Fulfillment。
- **数据迁移**：不涉及（表已存在）。
- **AC**：AC-62 全条；INV-45；AC-60/63 不升级。

## 4. 测试矩阵

| 场景 | 断言 |
|---|---|
| 正常释放 | commitment `RELEASED`、release 行、version+1、permit/订单/组不变 |
| 同 release_id 重试 | 返回首次结果，release 行/commitment 不重复 |
| 同 refund_id 不同 release_id | `REFUND_COMMITMENT_CONFLICT`，状态不变 |
| SETTLED / RELEASED | 拒绝，不双重扣减 |
| 金额不等 | 拒绝，零写入 |
| ≥100000 无 reviewed_by / 同人 | `REFUND_RELEASE_NOT_AUTHORIZED` |
| 过期 / 缺授权字段 | 拒绝，零写入 |
| order/group 不匹配 | `REFUND_COMMITMENT_CONFLICT` |
| 并发两释放 | 一个成功、一个返回当前状态 |
| trigger 不合法 | 拒绝（不把订单 CANCELLED 当退款申请终止） |

## 5. stop_conditions

- 若表结构不足以表达“授权撤销/角色”（当前无角色表/撤销字段）：停止并回 Architect/PO，
  不私自加字段或用字符串冒充。
- 若无法在不调用 Payment 的前提下排除“Payment 已退款但承诺仍 RESERVED”：停止在该场景，
  要求先对账；不自动释放。
- 若 CLI 无法保证“仅授权角色”执行：停止，改 RPC/网关鉴权方案，不在 CLI 里伪造角色。
- 任一测试失败：stop-the-line，不提交。
