# Design checklist（非规范）

> 操作辅助，冲突以宪法/AGENTS 为准。用于写 ADR、状态机、并发/恢复设计，或审查这类设计。

## 1. 状态所有权

- [ ] 每个核心状态字段只有一个写入服务/表/状态机。
- [ ] `PaymentCaptured`、`OrderSettled`、`InventoryReady`、`FulfillmentAllowed` 没有被一个 status 揉在一起。
- [ ] 状态迁移完整，无死胡同；每个终态可解释。
- [ ] 跨服务身份（order/payment/refund/group/warehouse）在契约里有归属，不只存在于代码。

## 2. 5 个崩溃窗口

逐条写“预期行为 + 恢复所有者”：

1. 本地提交后崩溃（DB 已写、RPC/事件未发）。
2. 跨服务 RPC 成功后崩溃（对方已执行、本地未提交）。
3. 消息重复 / 乱序 / 延迟到达。
4. 取消/确认竞态（谁赢、败者怎么退）。
5. 外部重放缺失（回调永久丢失、无轨迹）。

- [ ] 每个窗口有幂等键/唯一约束/CAS。
- [ ] 每个窗口有持久恢复任务/补偿/人工队列，不靠“外部会重试”。
- [ ] 每个失败有明确错误码/状态，不静默。

## 3. 反模式自省

- [ ] 没有用新增 if-else/局部锁/flag 默认 false 掩盖协议问题。
- [ ] 同一业务路径为同一类缺陷已有 2 处以上状态分支 → 停，回状态机/ADR。
- [ ] 没有把“当前实现”写成“设计”，没有让代码反向覆盖契约。
- [ ] 兼容期有默认消费者切换、收口条件、移除日期、回滚路径；不是永久 flag。

## 4. 契约与兼容

- [ ] 跨服务/对外接口有 contract owner、版本、兼容/回滚路径。
- [ ] 事件/接口有幂等、顺序/重试、超时语义；不是只有 schema。
- [ ] 数据迁移可回滚/可重跑；旧数据/旧消费者有过渡。
- [ ] 资金/库存/权限/履约准入有 fail-closed 与人工兜底。

## 5. 可验证性

- [ ] 每条关键决策能指向 AC/INV/测试/模型/可观测指标。
- [ ] 高风险设计有独立 oracle 或明确“没有 oracle，不能证明 intent”。
- [ ] 并发协议有 stateful property test/模型检查；不是只靠单测。
- [ ] 测试能杀死关键 mutant/negative control；不只是 happy path。

## 6. 备选与后果

- [ ] 至少一个被否决的备选及理由。
- [ ] 假设与不确定性单列；底层依赖风险写清。
- [ ] 后果包括运维/回滚/监控/人工队列成本。
- [ ] 没有把“以后再加”当设计。
