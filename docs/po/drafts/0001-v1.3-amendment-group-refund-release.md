# SPEC-0001 v1.3 修订草案 — 组退款后的预留释放口径

| 项 | 值 |
|---|---|
| 目的 | 解除 SPEC-0002 v1.3 的 C-1 前置条件：明确“组退款（普通售后/TCC 补偿/SYSTEM 缺货）后释放预留”与现有 `0001:287` 禁止条款的关系 |
| 目标文件 | `docs/specs/0001-fulfillment-quantity-split.md`（当前 v1.2，approved） |
| 触发 | `docs/collab/qc-reports/SPEC-0002-QC-03.md` C-1；`docs/po/drafts/0002-payment-settlement-admission.md` D-17 |
| 状态 | **draft**：未批准。批准后由 PO 原地升版 0001 到 v1.3，并同步变更记录与批准记录；在此之前 SPEC-0002 不得 `approved` |

## 1. 问题

SPEC-0001 v1.2 第 287 行（§6.6 表最后一行）写：

> 已支付订单 | 不得出现"预留已释放但订单仍为已支付"的状态组合（基线 INV-06）

但 SPEC-0001 自身又允许：
- 组级退款/缺货退款后，该组不再发货（AC-27、§6.7）；
- 已支付订单的多组场景下，单组退款不影响其他组发货（INV-38/AC-27）。

组退款在“未离仓”时必须释放或补偿释放该组预留，否则库存被永久占用；而订单生命周期仍是 `PAID`（退款态由 `refund_state` 投影表达）。因此该行需要限定为“**仍计划履约的组**”，否则 SPEC-0002 的组退款协议无法在 0001 下成立。

## 2. 拟修订内容（逐条）

### 2.1 §6.6 表最后一行替换

**原文**

```text
| 已支付订单 | 不得出现"预留已释放但订单仍为已支付"的状态组合（基线 INV-06） |
```

**改为**

```text
| 已支付订单 | **仍计划履约的组**不得出现"预留已释放且仍可继续发货"的状态组合（基线 INV-06）；已进入组级退款（`refund_state=REFUNDING/REFUNDED`）且许可已 `REVOKED`/运单已 `CANCELLED` 的组，其预留由退款准入释放或补偿释放，是合法结果，不构成该禁止组合 |
```

### 2.2 §6.6 增加“组退款库存处置”段（新增 6.6.1）

```text
#### 6.6.1 组退款后的库存处置

- 组退款来源包括：普通售后退款、TCC 补偿退款、SYSTEM 缺货退款；三者共用同一组级退款准入。
- 未离仓组（无运单 / 运单 CREATED / CANCELLED）：由 Inventory 释放该组预留；`HELD` 直接释放，`CONFIRMED` 走基线 `CancelConfirm` 的补偿释放。
- 已离仓组（运单 SHIPPED/RECEIVED 或带离仓时间的 EXCEPTION）：不得释放预留来“冲销”已发事实；退货回库仍按 INV-03，回库成功后再退款。
- 释放/回库失败必须重试并告警；释放后 `available ≤ on_hand`，且行数量守恒（INV-17），不得超卖或重复退款。
- 组退款不改变订单生命周期；退款进度只写 `refund_state`，不得写回 `orders.status`（INV-01/AC-25）。
```

### 2.3 AC-27 增加判定说明

**原文**

```text
**AC-27** 已退款未发组不卡住订单
Given 拆量订单 G2 退款完成、G1 正常发货
Then 订单投影按 G1 推进；G2 不得让订单停留在 ALLOCATED 或阻塞 G1 发货
```

**改为**（只追加解释，不改变断言）

```text
**AC-27** 已退款未发组不卡住订单
Given 拆量订单 G2 退款完成、G1 正常发货
Then 订单投影按 G1 推进；G2 不得让订单停留在 ALLOCATED 或阻塞 G1 发货
And G2 的预留释放/运单取消不构成 §6.6 禁止的组合；订单生命周期仍为 PAID/ALLOCATED/SHIPPED，
    G2 的退款进度由 refund_state 表达
```

### 2.4 §7.1 状态机（修正既有漂移）

SPEC-0001 §7.1 当前画了 `PAID --取消（仅未发货）--> CANCELLED`，与同文件 §6.7“已支付未发货不提供取消语义”冲突。本次升版一并修正：

**原文**

```text
PENDING_PAYMENT --支付确认--> PAID --首组发货--> ALLOCATED --全部发货--> SHIPPED --全部收货--> COMPLETED
       │                        │
       └──取消/超时/补偿──> CANCELLED <──取消（仅未发货）──┘
```

**改为**

```text
PENDING_PAYMENT --支付确认--> PAID --首组发货--> ALLOCATED --全部发货--> SHIPPED --全部收货--> COMPLETED
       │
       └──取消/超时/结算失败退款──> CANCELLED
（仅 PENDING_PAYMENT 可取消；PAID 后不提供用户取消；TCC 补偿/结算失败可进入 CANCELLED，见 §6.7）
```

### 2.5 §7.5 组合表备注

在 §7.5 的“G2 退款（未发）”行下增加备注：

```text
注：G2 REFUNDED 时其预留已由退款准入释放（§6.6.1），该释放合法，不构成 §6.6 禁止组合；
    订单生命周期仍为 ALLOCATED/PAID，G2 的退款态由 refund_state 表达。
```
