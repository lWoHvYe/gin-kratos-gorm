## 1. Payment/终态顺序核对

| 环节 | SPEC r5 | ADR r4 | 一致 |
|---|---|---|---|
| 24h 离开 OPEN | `0002-v1.8-amendment.md:154` 先 `OPEN/RESOLVING→COMPENSATING` | `amd1.md:293` 同 | ✓ |
| 补偿（permit/CancelIfCreated/INV-44） | `:154` 在 `COMPENSATING` 内完成 | `:295-296` 同 | ✓ |
| 退款意图持久化 | `:154` 只写“Payment.Refund 最后执行”，未显式写“先写 `refund_applications`” | `:297` 明确“先持久化 `refund_applications(PENDING)`，再 Payment” | **部分**（见 2 残留①） |
| Payment 最后 | `:154`“Payment.Refund 最后执行；**全部成功后才置 `EXPIRED_REFUND`**” | `:298`“Payment 成功后才 CAS `COMPENSATING→EXPIRED_REFUND`” | ✓ |
| 失败保持 | `:155`“保持 `COMPENSATING`，不提前 `EXPIRED_REFUND`” | `:299` 同 | ✓ |
| `EXPIRED_REFUND` 语义 | `:154` 全部成功后置终态 | `:298`“表示 Payment 退款已完成” | ✓ |

**结论：Payment/终态先后已一致**（Payment 成功后才 `EXPIRED_REFUND`；失败保持 `COMPENSATING`）；QC-13 B-1 闭合。

## 3. 非阻断残留（不阻止批准，建议批准时一并修正）

1. **SPEC r5 AC-63 未显式写“先持久化 `refund_applications`、再 Payment”**（`0002-v1.8-amendment.md:154`），而 ADR r4 `:297` 已写。实现按 SPEC 字面只要求“Payment 最后”，可能把退款意图放在 Payment 成功之后，弱化“支付前可恢复”的持久意图。建议在 AC-63 该条补一句“在 `COMPENSATING` 内先幂等写/复用支付级 `refund_applications(PENDING)`，再调用 Payment.Refund；成功后置 `DONE`；全部 `DONE` 后才 `EXPIRED_REFUND`”。
2. **SPEC §14 的 QC 行仍为历史 `CHANGES REQUIRED`**（`0002-v1.8-amendment.md` §14）；ADR §16 的批准记录也未引用 QC-13/QC-14。建议 PO 在提交 Human 前更新为 QC-14 结论，Architect 在 ADR 批准记录补引用。
3. MINOR：SPEC S16 的状态列表把 `COMPENSATING` 排在 `RESOLVED` 之后（`:82`），ADR A-04 为 `OPEN/RESOLVING/COMPENSATING/RESOLVED/...`；建议统一顺序，避免读者误读。
