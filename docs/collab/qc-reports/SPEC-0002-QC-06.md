## 1. 结论

**BLOCKED。** N-51（零元单定义）、N-52（未离仓分支穷举）、N-53（许可 CAS 败者）、N-54（`CANCELLED/REJECTED`）、N-55（错误码映射）、N-56（0001 修订）、N-57（目标状态视为成功）均已落位；N-50 的订单级→组级扇出也已建立（AC-51 `:213-219`）。

阻断在 **扇出的金额口径**：

- **N-58（BLOCKER）**：AC-50 的金额门比较"本次金额"与"该组剩余可退额度"，后者被定义为 `Σ 行剩余额度`（`:208`，商品口径），但同一 AC 又规定退款金额包含 `freight_share`（`:208`），AC-51 的组拆分也写作"行实付 + `freight_share`"（`:218`）。凡 `freight_share > 0` 的组，退款金额必然大于组剩余额度：未离仓组会落到 `:195` 的 `REFUND_ADMISSION_CONFLICT`（或 `:196` 的部分退款拒绝），`:197-202` 的整组退款分支永远进不去。含运费的订单的组退款在规格层面不可执行。
- **N-59（BLOCKER）**：AC-51 `:218` 按"行实付 + `freight_share`"（**原始组份额**）拆分，未扣减该组已发生的部分退款；而 AC-50 `:195` 以"该组剩余额度"为上限。已离仓且已部分退款的组，补偿金额（原份额）> 剩余额度 → 准入冲突；`:215` 又规定"任一组未取得准入结果 → 不得打款、整单可重试"，补偿会永久卡在重试。"累计不超过订单 `captured`"是订单级上限，不能替代逐组剩余上限。

其余：**N-60**（`AC-51:215` 与 `:217` 的"已全额退款组跳过"未写成 `:215` 的例外，可能被当成"未取得 PRE"卡住整单补偿）、**N-61**（`§6:385` 的 TCC 键仍是 `tcc:<payment_no>`，与 `AC-51:213` 的 `tcc:<payment_no>:<group_no>` 不一致）。

## 3. 五个定向攻击的回答

| # | 攻击点 | 回答 |
|---|---|---|
| 1 | TCC 扇出后订单级金额与组拆分之和是否可能 ≠ `captured`；"累计不超 `captured`"是否足够 | **原份额口径下，拆分之和 = `captured`（0001 INV-20/INV-21：Σ 行实付 + 运费 = 订单实付，Σ `freight_share` = 订单运费）；但存在两处不等：①`freight_share` 被计入退款金额、却未被计入组剩余额度（`Σ 行剩余`），含运费组必然触发 `:195` 冲突（N-58）；②已部分退款组的原份额 > 剩余额度（N-59）。"累计 ≤ `captured`"不够：它只防订单级超退，不防单组超其剩余额度，也不能避免"单组超退 + 另一组少退"的合计仍 ≤ `captured`。必须逐组以组剩余额度为上限，且拆分取剩余而非原始份额** |
| 2 | 部分组成功、部分组失败（含已离仓/已全额退款/冲突）时，"整单可重试"是否重复打款或漏打 | **准入阶段安全：`AC-51:215` 规定任一组无有效结果就不打款，不会先退一部分；重试时已 `REVOKED/CANCELLED` 的组按 `AC-50:199/:201` 幂等返回 `PRE`，`§2:90` 目标状态视为成功。打款阶段：`:219` 保留组级申请、按 `AC-50` 重试，支付键 `refund_id + payment_no` 幂等（§6 `:386`）可防重复打款；但**已打款组重试时变为"已全额退款"**，`:217` 的跳过若未被 `:215` 视为例外，就会把剩余未打款组也卡住（N-60）。永久冲突（如 `CONSUMED+无运单`，`:202`）会进入"整单可重试"的循环，只能靠 AC-61 `:277` 的告警/人工重放兜底，规格未定义补偿的终止/人工裁决态** |
| 3 | AC-50 未离仓分支是否互斥穷举；`CONSUMED+CANCELLED` 返回 `PRE_SHIP_REVOKED` 是否误认为可再发 | **穷举且互斥：**:198-202` 按（许可 × 运单）覆盖 9 种未离仓组合，无重叠。**不会误发**：该组许可仍为 `CONSUMED`、运单 `CANCELLED`；AC-48 `:183` 对不同 `shipment_no` 返回 `FULFILLMENT_NOT_ALLOWED`，同一 `shipment_no` 的 Ship 按 `:185`/§5.2 `:313` 返回 `SHIPMENT_CANCELLED`；`FulfillmentAllowed` 谓词（`:86`）要求 `S5=NONE`。但返回码 `PRE_SHIP_REVOKED` 与"许可仍是 `CONSUMED`"字面不一致，需说明它只表示"未发货退款、无运单可发"（N-64） |
| 4 | 零元单 0 元申请走 `REVOKED` 是否与 AC-40 一致 | **业务上一致**：`:195` 允许首次 0 元申请，进入 `:198` 的 `REVOKED` 分支，只撤销许可/取消运单、无实际打款，符合 AC-40 `:133`"只释放或回库、不产生打款"。**残余**：AC-50 `:208`/AC-51 `:218` 仍会计算并"逐组打款"0 元，未写"0 元申请由释放路径完成、不调用 Payment"（N-63）；另外 0001 的 `freight_share` 对零元单通常为 0，不影响 |
| 5 | 是否仍有代码级 BLOCKER | **有**：N-58（运费未纳入组剩余额度）、N-59（原份额 vs 剩余额度）。N-60/N-61 为 MAJOR。因此不满足 `PASS WITH CONDITIONS`（该结论只允许剩余 C-1/C-8/C-9） |
