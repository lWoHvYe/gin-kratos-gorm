# 项目宪法 v3.0（trial / reform/lean-core）

> 本文件是 trial 分支的目标版本，不是对 v2.2.0 的逐条补丁。评审标准：新设计自身是否自洽、
> 完整、可执行、达到目的；旧条款只作来源，不作为“必须兼容”的基线。
> 合并前需 reviewer/human；指标不改善则丢弃分支。

## I. 契约与变更

1. **行为变更先有 Spec。** 新增/修改行为或 AC 必须先有 Spec，经独立审查、人类批准后才能实现。实现变更按已批准 Spec 执行。
2. **bugfix 不设特殊路由。** 已有行为被破坏、且已被批准 Spec 覆盖、且不触及契约主题时，按实现变更处理；否则按契约变更处理。不得用“bug”名义绕过 Spec/ADR。
3. **ADR 触发。** 跨服务协议或事件、数据模型/迁移、状态机、并发控制方案、技术选型必须写 ADR；ADR 与 Spec 同批审查、同批批准。Spec 写业务/AC，机制写 ADR；plan 只承载不需要 ADR 的局部设计。
4. **一份能力一份权威 Spec。** 既有 `docs/specs/0001/0002` 暂冻结，不迁移、不复制；新能力用 `specs/<feature>/spec.md`。变更既有 Spec 时原地更新；不得同时维护两份权威。迁移另案。
5. **状态唯一来源。** 验收状态只在权威 Spec 的验收状态表；运行状态（裁决、冻结、批准、Release）只在 `docs/review-tracking.md`。plan/tasks/index/汇总文档不保存状态。

## II. 独立审查

6. **审查者不是作者。** 审查者必须是另一个 agent 实例，不参与写作；只依据 Spec/ADR、精确 base/head 的代码、plan 与测试日志，不依据作者自述。
7. **问题可溯源。** 每条阻断必须指向 AC、领域不变量、已批准 ADR、Spec 必备章节或本宪法条款；摘不到的记 `[TODO]`，不阻断。权限、安全、数据完整性、迁移、资金、库存风险必须阻断。
8. **不给补丁、不替作者设计。** 审查者只指出违反项；设计缺陷回 Spec/ADR；不在 review 里用“加锁/加 if”收敛。
9. **一次给全、有界升级。** 审查者同一轮列全 blocking 问题；作者一次修完，只复跑失败项+diff。超过 2 轮不收敛，由人类按“实现错误/证据不足/设计问题/契约缺口/环境”分类决定下一步；不得因轮次放行高风险阻断。
10. **PASS 语义。** 实现 PASS 不等于 Spec 全量验收，也不等于 Release；审查者只把有证据支撑的 AC 标为已验证。AC 状态只由审查者写。

## III. 证据

11. **口头 done 无效。** 行为变更必须附实际执行日志，绑定精确 HEAD；纯文档不得声称测试通过。可能使其他 Spec 已验证 AC 失效的变更，必须列出 AC 与非回归证据。
12. **高风险证据。** 资金、库存、履约、权限、跨服务、迁移、状态机的变更必须有并发/故障注入或等价负例；不适用须人类书面豁免。Mock 必须符合真实业务边界，至少一个异常分支。
13. **交付三件事。** 每次交付写【测试范围】【未覆盖范围】【取舍】。不得用测试绿灯冒充 intent-level 验证；没有独立 oracle 的 claim 只能标“未验证”。
14. **不伪造。** 不得自标 AC `[x]`；未审写 `Reviewed-by: pending`，不得冒充已审；不得用 hotfix/新 change_id/缩范围绕过 FAIL。

## IV. 人类裁决

15. **人类批准点。** 批准 Spec（含链接 ADR）、合入、Release；回答业务裁决题。人类不逐条核对语法/文字。
16. **作者不得自行决定。** 业务取舍、契约/状态所有权变更、架构缺陷交人类或回 Spec/ADR；范围内缺陷由作者修。
17. **豁免逐台账。** 写明范围、期限、受影响不变量；无期限无效；无记录视为不存在。

## V. 领域不变量（违反即错）

18. **全局幂等。** 跨服务写必须以数据库唯一约束或状态机 CAS 兜底；不得只靠 Redis。
19. **事务与恢复。** DTM Saga 走 `dtm.Branch`；业务写与 `outbox.Append` 共用 `*sql.Tx`；`gid` 确定性派生。跨服务资金/库存/履约写入必须有持久任务或工作流驱动；外部重试/消息重放/进程崩溃不得作为唯一恢复。
20. **事实所有权。** `PaymentCaptured`、`OrderSettled`、`InventoryReady`、`FulfillmentAllowed` 是不同事实，不得由一个 status 或 `order.paid` 合并。普通售后、TCC 补偿、SYSTEM 退款必须同一组幂等准入，由 permit 裁决退款/发货竞态；已发货只退款不回滚履约；`REVOKED` permit 不得由实现自行恢复；commitment 创建/释放按已批准 Spec/ADR。
21. **读写隔离与多仓。** `skus.stock` 是投影，真实库存在 inventory；必须 Read-Your-Writes。多仓操作/事件/恢复/replay 显式携带 `warehouse_id`；需要组身份的履约事件不得缺省 G1。
22. **静态守卫。** 跨服务禁包引用；`internal/platform` 不依赖 `services`；事务核心用 `database/sql` + 条件 `UPDATE`；GORM 仅读侧限定文件；对外错误用 `apperr`；不改生成物。

## VI. 安全与边界

23. **AI 可选。** `ai` 故障不得影响浏览、下单、支付；AI 走统一 `Turn/Action`；写操作“草案→人工确认→RPC”；身份只来自服务端。
24. **技术栈。** 不引入未批准技术栈；无测量不做极值优化；dev 压测 ≤100k/1M RPS；`main` 不新增半成品协议路径。

## VII. 流程修改

25. **流程变更先试点。** 修改本宪法/AGENTS/核心流程必须从最小增量开始，写明可验证收益与停止条件；无数据不把假设写成硬规则。非规范 checklists/guides 不是验收依据。
26. **不新增角色/状态。** 除非人类批准；优先用现有作者/审查者/人类三角色，状态只落 Spec 验收表与台账。

## Governance

- 本宪法 > AGENTS；冲突以本宪法为准。
- 修订：作者起草、审查者审查、人类批准；删除/重定义原则为 MAJOR，新增规则为 MINOR，澄清为 PATCH。
- 版本：v3.0（trial）。批准前不生效；trial 分支不合并到 release。
